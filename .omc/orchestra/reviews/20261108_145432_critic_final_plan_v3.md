1. **음성 감정 인식의 추가 가치가 검증되지 않는다 — 심각도: 상**  
   **지적:** §5의 ‘확인 질문 ON/OFF’ 비교는 질문 자체의 효과와 음향 감정 분석의 효과를 분리하지 못한다. 원 설계서에 고객 가치 가설이 있어도, 비싼 SER을 추가해야 하는 이유는 여전히 검증되지 않는다.  
   **수정 제안:** 동일한 질문 정책에서 ‘텍스트만 사용’과 ‘텍스트+음성 감정 사용’을 비교하고, 이해받음·불편함·재사용·추가 비용을 함께 평가하라.

2. **emotion2vec+의 출력 사양을 확대 해석했다 — 심각도: 상**  
   **지적:** §3.2는 ‘9라벨 softmax + 정서가·각성’을 모델 출력으로 적고 A등급을 붙였다. 그러나 인용한 공식 모델카드는 9개 범주와 임베딩을 설명하며, 해당 모델이 연속 VA 점수를 직접 제공한다는 근거는 없다. [공식 모델카드](https://huggingface.co/emotion2vec/emotion2vec_plus_base)  
   **수정 제안:** VA를 생성할 별도 회귀 헤드, 학습 데이터, 척도, 검증 방법과 구현 일정을 명시하라.

3. **9개 모델 라벨에서 5개 제품 감정으로 가는 변환이 빠졌다 — 심각도: 상**  
   **지적:** ‘분노→답답함’, ‘슬픔→가라앉음’, ‘공포→불안’은 동의어 변환이 아니다. 로짓 마스킹으로 새로운 감정 개념을 만들 수도 없다. 특히 범주 밖 입력을 제거하고 재정규화하면 남은 감정의 신뢰도가 부풀 수 있다.  
   **수정 제안:** 제품 라벨별 조작적 정의와 독립 평가셋을 만들고, 제한된 4범주 벤치마크용 마스킹과 실제 서비스의 범주 밖 입력 처리를 구분하라.

4. **평가 과제가 제품 주장을 검증하지 못한다 — 심각도: 상**  
   **지적:** 평가용 4감정에는 불안·답답함·지속적 가라앉음이 없다. 따라서 4감정 UA가 높아도 제품의 핵심 라벨이 타당하다는 결론은 나오지 않는다. 논문 A의 RQ3도 불안·가라앉음의 ‘대리 클래스’가 무엇인지 정의하지 않았다.  
   **수정 제안:** 벤치마크 성능과 제품 라벨 타당성을 별도 게이트로 두고, 대리 지표를 사용할 경우 실제 개념과의 일치도를 검증하라.

5. **결합 규칙 세 가지의 실행 관계가 불명확하다 — 심각도: 중**  
   **지적:** §3.3에는 ‘글이 극성을 먼저 결정’, ‘모달리티별 가중 평균’, ‘불일치하면 평균하지 않고 질문’이 함께 있다. 어떤 규칙이 우선인지, 글이 오인식됐거나 한 모달리티가 누락됐을 때 어떻게 처리하는지 없다.  
   **수정 제안:** 입력 품질·불일치·보류·위기 조건별 우선순위를 정하고, 각 분기의 오류와 질문 발생률을 따로 측정하라.

6. **‘온도 보정 후 확률’이라는 설명만으로 보정이 성립하지 않는다 — 심각도: 상**  
   **지적:** Claude가 출력하는 점수가 로짓인지, 생성된 자기평가 숫자인지 정의되지 않았다. 모달리티별 보정을 했다고 결합 결과까지 보정되는 것도 아니다. 온도 보정이 분포 변화 이후에도 신뢰도를 보장하지는 않는다.  
   **수정 제안:** 점수의 생성 방식과 보정 대상을 명시하고, 최종 결합 출력도 독립된 보정·평가 세트에서 검증하라.

7. **감정 점수에서 위기 위험도로 넘어가는 근거가 없다 — 심각도: 상**  
   **지적:** §3.3의 `위험도 = max(글, 소리)`는 두 값이 같은 사건의 위험을 같은 척도로 측정한다는 전제가 필요하다. 감정 분류 확률이나 높은 각성은 곧 위기 확률이 아니다. 최대값 규칙은 오탐을 늘릴 수도 있다.  
   **수정 제안:** 위기 판정의 정답 기준과 음성 단서의 추가 기여를 별도로 평가하고, 재현율뿐 아니라 정밀도·오탐 빈도·불필요한 안전 모드 전환을 보고하라.

8. **안전 스크립트를 끊을 수 없게 하는 제안은 근거가 부적절하다 — 심각도: 상**  
   **지적:** §1.2에서 인용한 `interruptible`은 구현 기능의 존재를 보여줄 뿐, 위기 상황에서 끼어들기를 막는 것이 적절하다는 근거가 아니다. 사용자의 중지 요청이나 상황 정정까지 차단할 수 있다.  
   **수정 제안:** 명시적 중지·종료·정정은 항상 처리하도록 하고, 필요한 안내를 짧은 단위로 나눠 중단 후 재개 정책을 검증하라.

9. **보류 도입을 성능 개선과 혼동하며 합격선을 완화한다 — 심각도: 상**  
   **지적:** §6 #2의 ‘전체 커버리지 UA 0.70’과 ‘커버리지 75%에서 UA 0.70’은 다른 과제다. 어려운 발화를 제외한 점수 상승은 전체 인식 능력 향상의 증거가 아니다. 보류 후 열린 질문이 얼마나 유용한지도 측정하지 않는다.  
   **수정 제안:** 전체 성능 하한을 유지하면서 선택적 성능을 별도로 보고하고, 보류에 따른 질문 부담·이탈·오류 수습까지 합격 조건에 포함하라.

10. **보류 평가의 분모와 위험 정의가 빠졌다 — 심각도: 상**  
    **지적:** 전체 커버리지 75%를 맞춰도 특정 감정이나 사용자군은 대부분 거부될 수 있다. AURC의 위험이 전체 오분류율인지, 클래스별 균형 오류인지도 불명확하다. ‘가장 확실한 결과는 보류 곡선’이라는 표현 역시 개선을 미리 가정한다.  
    **수정 제안:** 위험 함수를 정의하고 감정별·화자군별 커버리지와 오류를 보고하라. 임계값은 보정 세트에서 고정하고, 테스트에서는 실제 커버리지를 측정하라.

11. **‘1%p 차이는 노이즈’는 통계적으로 성립하지 않는다 — 심각도: 중**  
    **지적:** §4.1은 개별 시스템의 신뢰구간 폭으로 시스템 간 차이를 단정한다. 같은 화자에서 측정한 두 모델은 상관돼 있으므로, 개별 신뢰구간의 중첩만으로 차이의 유의성을 판단할 수 없다.  
    **수정 제안:** 동일 화자·동일 분할에서 얻은 성능 차이에 대해 대응 비교와 차이의 신뢰구간을 계산하라.

12. **유의하지 않은 결과를 ‘차이가 작다’는 근거로 사용한다 — 심각도: 중**  
    **지적:** §3.1의 86% 대 92%, `p=0.1`은 차이를 검출하지 못했다는 뜻이다. 두 방법의 차이가 작거나 동등하다는 증거는 아니다.  
    **수정 제안:** 차이의 신뢰구간을 제시하고, 동등성을 주장하려면 허용 차이를 사전에 정한 동등성 검정을 사용하라.

13. **표본 수에 비해 정밀도를 낙관한다 — 심각도: 상**  
    **지적:** §4.5의 ‘200발화에서 ±6.4%’는 독립적인 이항 정확도에 대한 근사다. 10명에게서 반복 수집한 발화와 클래스별 재현율 평균인 UA에 그대로 적용할 수 없다. §1.3의 동일한 50턴으로 9칸을 튜닝하고 성능을 평가하면 선택 편향도 생긴다.  
    **수정 제안:** 화자·세션 내 상관과 클래스별 표본 수를 반영하고, 튜닝용 발화와 최종 평가용 발화를 분리하라.

14. **화자 분리와 세션 분리를 동등하게 취급한다 — 심각도: 상**  
    **지적:** §3.5의 ‘화자 또는 세션 완전 분리’는 동일한 조건이 아니다. 대화 상대가 훈련셋에 남으면 같은 대화 내용·환경을 공유할 수 있고, 텍스트 맥락을 붙일 때 문제가 커진다. Hyeon의 화자 LOSO는 명시적으로 화자 단위 분할이다. [Hyeon 원문](https://arxiv.org/html/2410.12416v1)  
    **수정 제안:** 기존 연구 재현용 화자 LOSO와 제품 일반화 검증용 대화쌍·세션 분리를 별도로 보고하라.

15. **실시간 평가에 미래 정보가 들어갈 여지가 있다 — 심각도: 상**  
    **지적:** §3.5의 짧은 입력 ‘앞뒤 병합’은 뒤 발화가 도착해야 가능하다. 개인 기준선을 전체 세션으로 계산하거나 소수 샷 등록 발화를 시간 구분 없이 고르면, 실제 응답 시점에 없던 정보가 평가에 들어갈 수 있다.  
    **수정 제안:** 각 예측 시점에 사용할 수 있는 과거 정보만 허용하고, 등록 발화·적응 발화·평가 발화를 시간순으로 분리하라. 병합 대기시간도 지연에 포함하라.

16. **사용자 확인 응답을 독립적인 정답으로 취급할 위험이 있다 — 심각도: 상**  
    **지적:** §4.5의 ‘맞아/아니야’는 모델이 먼저 제시한 감정에 대한 반응이다. 유도 질문, 동의 편향, 질문 대상으로 선택된 발화의 편향이 섞인다. 음성 인상·맥락 해석·자기보고도 서로 다른 측정 대상이다.  
    **수정 제안:** 세 라벨을 구분해 저장하고, 일부 표본에는 모델 예측을 보여주지 않은 독립 자기보고와 블라인드 평가를 확보하라.

17. **개인 기준선을 만들었다고 감정 변화가 분리되는 것은 아니다 — 심각도: 중**  
    **지적:** §3.6의 3턴·30초에는 ‘평소 상태’를 대표한다는 근거가 없다. 처음부터 기분이 가라앉은 사용자라면 그 상태가 기준선이 된다. SSL 임베딩도 발화 내용·기기·화자 특성을 포함하므로 F0 대신 쓰는 것만으로 문제가 해결되지 않는다.  
    **수정 제안:** 기준선의 수집 기간·갱신·기기 변경 처리와 상태 오염을 정의하고, 기준선 없는 모델 대비 이득을 검증하라.

18. **R3은 소프트 라벨의 효과를 분리하지 못한다 — 심각도: 상**  
    **지적:** R3은 소프트 타깃·균형 샘플링·MixUp·클래스 가중·모델 수프를 동시에 추가한다. 개선돼도 원인을 알 수 없다. 투표 파일이 없으면 focal 등으로 대체한다는 계획은 논문 A의 핵심 연구 질문 자체를 바꾼다.  
    **수정 제안:** 최소한 하드/소프트 라벨만 바꾸는 대응 실험을 확보하고, 투표 파일 미확보 시에는 논문 기여와 제목을 재설정하는 별도 경로를 두라.

19. **서로 다른 벤치마크를 성능 상한처럼 연결한다 — 심각도: 상**  
    **지적:** §4.1·§7.1에서 영어 8범주 macro-F1 0.43, MELD UA 31.54, 한국어 4범주 UA 66.26을 연결해 목표의 난도를 설명한다. 클래스 수·코퍼스·주석·훈련 조건이 달라 한국어 목표의 달성 가능성을 정량적으로 추론할 수 없다. ‘영어 성능 논문에는 93팀 상위권이 필요’하다는 주장도 근거가 없다.  
    **수정 제안:** 각 수치는 해당 과제의 관측 결과로 한정하고, 한국어 목표는 동일 프로토콜의 직접 실험으로 정하라.

20. **신규성 판단을 검색 부재에 지나치게 의존한다 — 심각도: 상**  
    **지적:** §4.2의 ‘한국어에서 처음 검증’, §4.3의 ‘방법론적 빈칸’은 검색 범위 이상의 주장이다. 추가 검색에서는 이미 온도 보정과 선택적 위험 평가를 함께 다룬 2026년 SER 연구가 확인된다. 이것이 한국어 기여를 부정하지는 않지만, 단순한 방법 조합의 신규성 근거는 약해진다. [SURBN 논문 초록](https://www.sciencedirect.com/science/article/abs/pii/S0950705126017466)  
    **수정 제안:** 가장 가까운 연구와 데이터·방법·평가·발견을 대조하고, ‘최초’ 대신 실제로 입증할 차별적 기여를 정의하라.

21. **사전학습 오염 가능성을 일관되게 다루지 않는다 — 심각도: 상**  
    **지적:** §3.7은 학습 데이터가 미공개라고 하면서 이슈 표에서는 ‘KEMDy는 없음’이라고 단정한다. EmoBox 목록에 없다는 사실만으로 전체 의사 라벨 사전학습 데이터에 없다고 결론낼 수 없다. ‘제로샷’이라는 명칭도 오염 부재를 보장하지 않는다.  
    **수정 제안:** 공개적으로 확인된 포함·제외와 미확인 영역을 구분하고, 새로 수집한 독립 평가셋으로 보완하라.

22. **A등급이 근거의 강도로 오인될 구조다 — 심각도: 중**  
    **지적:** 원문 확인, 벤더 자체 시험, GitHub 사용자 보고, 팀 추론이 같은 A 표기를 공유한다. 특히 §3.3의 ‘A—추론값임을 확인’은 가중치의 타당성을 검증한 것처럼 읽힌다. 주장 1,222건도 독립적인 증거 1,222개가 아니다.  
    **수정 제안:** ‘출처 확인 수준’과 ‘연구 품질·제품 적용 가능성’을 분리하고, 팀 설계값에는 일관되게 설계 가설 표기를 사용하라.

23. **표에서 제한한 주장을 요약에서 다시 과장한다 — 심각도: 중**  
    **지적:** §2.1 표는 MOS 천장의 일반화를 부정하지만 바로 아래에서는 ‘문장 MOS는 천장이라 후보를 못 가른다’고 단정한다. KoCC-TTS 반례를 인정한 뒤 ‘W4가 첫 한국어 데이터’, §7.2에서는 한국어 대화형 TTS 평가가 ‘없다’고 적는다. §7.1의 ‘라벨 데이터 부재’도 KEMDy20의 존재와 충돌한다.  
    **수정 제안:** ‘없음’, ‘접근하지 못함’, ‘특정 프로토콜의 선례 미확인’을 구별하고 요약에도 동일한 범위 제한을 적용하라.

24. **지연 목표의 실행 가능성을 뒷받침하는 예산이 없다 — 심각도: 상**  
    **지적:** §1.1의 P90 1.5초 목표와 §1.3의 추가 대기 최대 2초가 어떤 조건에서 양립하는지 없다. VAD 기반 시각을 기준점으로 쓰면 말 끝 판정 오류가 지연 측정에도 영향을 준다. P90 1.5초는 모든 턴의 ‘상한’도 아니다.  
    **수정 제안:** 실제 발화 종료부터 말 끝 판정·STT·LLM·TTS·재생까지 시간을 분해하고, 조건별 지연 분포와 초과율을 보고하라.

25. **끼어들기 규칙에 필요한 정보가 300ms 안에 확보되지 않는다 — 심각도: 상**  
    **지적:** §1.2의 ‘1초 미만 발화인지’는 발화가 끝나야 알 수 있다. 즉시 덕킹하는 것과 300ms 이내 재생을 정지하는 것도 다르다. ‘전사가 없으면 거짓 끼어들기’라는 규칙은 ASR 실패나 비언어적 중단 의사를 놓칠 수 있다.  
    **수정 제안:** 감쇠·일시정지·재개·취소를 분리하고 판정 대기 상한을 정하라. 전사 실패와 실제 거짓 감지를 구분하는 평가를 추가하라.

26. **필러 규칙의 설명과 구현 조건이 충돌한다 — 심각도: 중**  
    **지적:** §1.5는 필러를 ‘4초 가까이 갈 때의 안전판’이라 설명하지만 실제 조건은 1초 시점의 첫 문장 미도착이다. 첫 문장이 없다고 TTFA가 반드시 1.5초를 넘는 것도 아니며, §6에서는 ‘LLM 미도착’으로 기준이 다시 모호해진다.  
    **수정 제안:** 첫 토큰·첫 문장·첫 오디오를 구분하고, 예상 잔여 지연에 따른 발동·취소·본응답과의 충돌 규칙을 정하라.

27. **W4 실험으로 맥락의 효과를 입증할 수 없다 — 심각도: 중**  
    **지적:** §2.2는 맥락을 제공한 상태에서 시스템을 비교하지만, 같은 질문으로 평가하는 맥락 없음 조건이 없다. 따라서 후보 선호도는 비교할 수 있어도 대화 맥락의 인과 효과는 분리할 수 없다. 이전 응답 음성의 화자도 후속 음성과의 연결감에 영향을 줄 수 있다.  
    **수정 제안:** 맥락 유무를 교차한 조건을 추가하고, 이전 응답 화자를 통제하라. 이를 하지 않으면 연구 주장을 맥락 조건의 시스템 비교로 제한하라.

28. **‘30명·30문항’이 검정력을 보장하는 것처럼 쓰인다 — 심각도: 중**  
    **지적:** R70의 순위 안정성은 해당 자료의 재표집 결과다. 현재 설계는 여러 단계·후보·문항 유형으로 평가가 나뉘므로 각 비교의 유효 표본 수가 훨씬 작다. ‘시스템당 12~15문항’과 20~25분 내 전체 절차가 양립하는지도 산출되지 않았다.  
    **수정 제안:** 참가자별 실제 청취·평정 횟수와 문항별 평가자 수를 표로 만들고, 파일럿 시간 측정과 검정력 모의실험으로 규모를 정하라.

29. **TTS 통계 분석과 전환 기준이 서로 맞지 않는다 — 심각도: 중**  
    **지적:** 반복 평가를 단순 이항검정으로 합치면 청취자·문항 간 의존성을 무시한다. ‘CMOS 유의 또는 승률 60%’는 여러 성공 경로를 허용하며, 승률의 신뢰구간이나 오류율 비열등성 기준도 없다. Holm 보정의 적용 범위도 불명확하다.  
    **수정 제안:** 주지표 하나와 비교군을 사전 지정하고, 반복측정 구조를 반영하라. 선호도 개선과 오류율 허용 한계를 함께 판정하라.

30. **TTS 통제 조건이 평가하려는 차이를 제거할 수 있다 — 심각도: 중**  
    **지적:** §2.2는 운율·타이밍을 핵심으로 삼으면서 앞뒤 무음을 모두 100ms로 고정한다. 이 처리는 엔진별 실제 쉼 차이를 제거할 수 있다. 성별·연령대 일치만으로 목소리 취향과 엔진 품질도 분리되지 않는다.  
    **수정 제안:** 편집된 음질 비교와 실제 서비스 출력 비교를 구분하고, 결과가 ‘엔진’인지 ‘엔진+선택 화자’에 대한 평가인지 명시하라.

31. **TTS 교체 기준에 사업성과 운영 조건이 빠졌다 — 심각도: 상**  
    **지적:** §2.2의 전환 기준은 선호도와 오류율 중심이다. 자체 호스팅 비용, 동시 접속 지연, 스트리밍 취소, 재생 위치 추적, 유지보수 공수가 빠져 있다. 원 설계서에 비용 가설이 있어도 v3에서 추가한 후보의 비용은 다시 계산해야 한다.  
    **수정 제안:** 청취 개선과 함께 세션당 원가·동시 부하 P90·운영 공수·필수 기능 지원을 전환 게이트에 포함하라.

32. **420인시를 추가 연구에 쓸 수 있는 자원처럼 다룬다 — 심각도: 상**  
    **지적:** 420인시는 기존 제품 개발을 포함한 7주 전체 공수다. 같은 가정이면 W3~W7의 AI 담당 가용시간은 약 75시간이다. GPU 실행 중에도 데이터 준비·오류 분석·주석·보고는 사람이 해야 한다. ‘GPU가 혼자 도는 시간’은 인력 충돌의 해결책이 아니다.  
    **수정 제안:** 역할별 잔여 시간을 기준으로 제품·연구·평가 공수를 배정하고, 추가 업무마다 삭제하거나 연기할 기존 업무를 지정하라.

33. **실험량과 선행 조건이 일정에 반영되지 않았다 — 심각도: 상**  
    **지적:** R1만 해도 5백본×학습률 2×은닉 2×5-fold이면 100회 헤드 학습이다. 이후 실험·반복 시드까지 포함한 산출표가 없다. W3에는 데이터 신청과 R0·보류 곡선 확정을 동시에 요구하지만, 보정 실험 R7은 W5다.  
    **수정 제안:** 데이터·투표 파일·GPU 확보를 선행 조건으로 연결하고, 최소 실험 묶음과 전체 실험 묶음을 나눠 시간·비용을 계산하라.

34. **R0의 중단 기준이 주관적이며 프로토콜 차이를 무시한다 — 심각도: 중**  
    **지적:** ‘WA 71.79 근방’에는 허용 오차와 반복 횟수가 없다. 원 논문의 5-fold 결과는 훈련 세트 20%를 검증에 사용한 조건이므로, 문서의 엄격한 검증 화자 분리와 같은 조건인지 먼저 확인해야 한다. 점수 차이가 곧 코드 오류는 아니다. [emotion2vec 원문](https://aclanthology.org/2024.findings-acl.931.pdf)  
    **수정 제안:** 체크포인트·분할·전처리·헤드·검증 방식·시드를 고정한 재현 기준을 만들고, 원문 재현과 강화된 평가 프로토콜을 구분하라.

35. **연구용 데이터가 제품 설정으로 넘어가는 권한이 확인되지 않았다 — 심각도: 상**  
    **지적:** §4.5는 KEMDy의 상업 조건을 미확인으로 두면서 제품 결합 가중치에 사용하고, R7 결과를 서비스에 바로 반영한다. 연구 이용 승인만으로 제품 학습·보정·파생 모델 배포·외부 ASR 전송까지 허용된다고 볼 근거는 없다.  
    **수정 제안:** 데이터별 허용 행위를 확인하고, 권한이 불명확한 결과가 제품 설정·가중치에 반영되지 않도록 배포 조건을 명시하라.

36. **‘KEMDy만 쓰면 IRB 없이 가능’은 단정할 수 없다 — 심각도: 상**  
    **지적:** §4.5는 연구대상 여부·심의면제·면제 확인 절차를 한 문장으로 생략한다. 공용IRB는 심의면제도 사전에 연구계획서를 제출하도록 안내한다. W4 청취 실험과 연구용 평가자 참여의 검토 경로도 일정에 없다. [공용IRB 신청 안내](https://public.irb.or.kr/pt/pt01/PT0102/PT0102R03.do)  
    **수정 제안:** 데이터 이용 연구와 청취·사용자 연구를 나눠 해당 기관에 대상 여부와 필요한 절차를 확인하고, 완료 시점을 모집·수집 이전 일정에 연결하라.

37. **‘확정안’의 범위와 항목 수가 일관되지 않는다 — 심각도: 하**  
    **지적:** 서두는 확정안이지만 본문에는 회의 승인 전 제안값·미확정 규칙이 섞여 있다. ‘13단계 중 즉시 7개, 나머지 8개’도 중복 관계를 설명하지 않으면 합계가 맞지 않는다. 위험도 최대값 규칙은 ‘회의 신규’인데 §6 결정표에 명시적으로 들어 있지 않다.  
    **수정 제안:** 승인 상태와 항목 ID를 통일하고, 기존 13단계와 새 목록의 대응표 및 누락된 결정 안건을 정리하라.
