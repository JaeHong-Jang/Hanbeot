## 0. 세 줄 요약

1. **단위(E)**: 어절만 피하면 다 비슷함
    - 어절(띄어쓰기) 단위만 확실히 나쁨 (NSMC **69.0%**)
    - 음절·형태소·서브워드는 **1~2%p 안쪽**으로 비슷함 (82.7~84.3%)
    - 한벗은 Claude가 텍스트를 직접 읽음 → **토큰화 단위를 고를 일이 사실상 없음**
    - 별도 분류기를 둔다면 → 사전학습 모델(KcELECTRA, KLUE-RoBERTa)에 딸린 토크나이저를 그대로 씀
2. **LLM의 약점은 단위가 아니라 라벨 수**
    - 긍부정 2클래스(NSMC): GPT-4 zero-shot ≈ 미세조정 모델 (F1 **88.0** vs 88.6)
    - 28클래스 감정(GoEmotions): macro-F1 **12.5%**로 무너짐
    - 1,000문장 중 **89개**에 목록에 없는 라벨을 지어냄
    - → Claude에게는 **적은 수의 고정 라벨 + 정서가·각성 점수**를 출력하게 해야 함
3. **체계(F)**: 2층 구조 추천
    - 데이터셋마다 라벨이 다름("AI Hub 7감정"만 해도 최소 3가지 버전) → 공통표가 꼭 필요
    - ① SER 성능 비교용: **4감정(기쁨·슬픔·분노·중립)**
    - ② 서비스 판단용: **5감정(+불안)과 정서가·각성 점수**
    - **외로움·우울(저각성 부정)**, **편안함(저각성 긍정)**은 어떤 범주형 체계에도 없음 → 정서가·각성 축으로 잡아야 함

# E. 한국어 텍스트 감정 분석의 단위·전처리

## E-1. 한 줄 결론

**토큰화 단위는 "어절만 피하면" 감정 분류 성능 차이가 1~2%p 이내임.**

- 한벗은 Claude가 문장을 통째로 읽음 → 단위 선택은 거의 의미가 없음
- 성능을 더 크게 좌우하는 것: **STT 오류율(WER)**과 **LLM 출력 라벨 설계**

## E-2. 쉬운 개념 설명

한국어 문장 "친구가 외로웠대요"를 컴퓨터가 읽으려면 먼저 조각(토큰)으로 나눠야 함. 나누는 방법은 크게 다섯 가지임.

| 단위 | 예시 | 장점 | 단점 |
|---|---|---|---|
| **어절** (띄어쓰기) | `친구가` / `외로웠대요` | 가장 단순함 | "외로웠대요", "외로웠어", "외롭다"가 전부 다른 단어가 됨 → 처음 보는 단어(OOV)가 폭증 |
| **형태소** | `친구/가/외롭/었/대요` | 뜻의 최소 단위라 의미가 깔끔함 | 형태소 분석기(Mecab, Okt, Komoran, Kiwi)가 필요하고, 띄어쓰기·맞춤법이 틀리면 분석이 틀어짐 |
| **음절** | `친/구/가/외/로/웠/대/요` | 사전이 작고(약 2천 개), OOV가 거의 없음 | 문장이 길어지고, 뜻 단위가 흐려짐 |
| **자모** | `ㅊ/ㅣ/ㄴ/...` | 오타에 강함 | 문장이 아주 길어짐 |
| **서브워드** (BPE, WordPiece, SentencePiece) | `친구/가/외로/웠/대요` | 자주 나오는 조각을 통계로 자동 학습. 요즘 사전학습 모델의 표준 | 언어학적 경계와 어긋날 수 있음 |
| **형태소 + 서브워드** | 형태소로 먼저 나눈 뒤 BPE | 둘의 장점을 합침. KLUE 모델이 이 방식 | 형태소 분석기 의존이 남음 |

**왜 지금은 덜 중요한가?**

- 2020년 전후: 모델을 처음부터 학습시킴 → 단위가 중요했음
- 지금: 사전학습된 모델(KcELECTRA, KLUE-RoBERTa)이 자기 토크나이저를 가짐 → 그대로 쓰는 게 원칙 (바꾸면 사전학습 효과가 사라짐)
- Claude 같은 LLM: 자체 토크나이저로 원문을 그대로 읽음 → 사용자가 형태소 분석을 해서 넣을 이유가 없음

**한벗에서 진짜 문제가 되는 전처리 이슈**는 따로 있음.
- **STT 오류**: 오인식이 생기면 감정 단어 자체가 틀리게 적힐 수 있음.
- **띄어쓰기 오류**: RTZR 출력은 띄어쓰기를 해 주지만, 오류가 있으면 형태소 분석기 기반 모델이 흔들림.
- **비유창성**: "어… 그게… 음…" 같은 머뭇거림, 반복, 끊긴 문장. 감정 단서이기도 해서 무작정 지우면 안 됨.

## E-4. 논문별 요약

### E1. Park 외 · 2020 AACL

> **한 줄:** 같은 모델에 문장 쪼개는 방법(토큰화)만 바꿔 가며 성능을 비교한 연구

- **참고:** 확인 요청받은 핵심 논문이며 실제로 존재함 (카카오브레인)
- **어떻게:** 같은 BERT 구조를 토큰화 방식만 바꿔 각각 사전학습
- **비교 과제:** 기계번역, KorQuAD, KorNLI, KorSTS, NSMC, PAWS-X
- **결과:** "형태소 분석 후 BPE"가 번역·대부분의 이해 과제에서 최고 (KorQuAD만 순수 BPE가 최고)
- **NSMC(영화 리뷰 긍부정):** 형태소+BPE **84.29** · 순수 BPE **83.52** · 음절 **82.7** → 차이 작음
- **눈여겨볼 점:** 어절 단위만 **69.0**으로 급락 → 어휘 64K로도 처음 보는 단어(OOV)가 너무 많음

### E2. 김진성 외 · 2021 한국융합학회논문지

> **한 줄:** 쪼개는 단위 4가지를 RoBERTa로 비교한 한국어 연구

- **어떻게:** RoBERTa로 어절·형태소·음절·자모를 비교
- **결과:** 문장 분류(NSMC·KorNLI·KorSTS)는 자모, 단어 분류(NER·SRL)는 음절이 최고
- **눈여겨볼 점:** NSMC 이득은 최대 **0.62%p** → 감성·감정 분류에서 단위 효과는 작음 (E1 결론과 같음)

### E3. KLUE · 2021

> **한 줄:** 한국어 이해 시험 세트(벤치마크)와 기본 모델을 공개한 연구

- **무엇:** 한국어 이해 벤치마크 + KLUE-BERT/RoBERTa 모델 공개
- **어떻게:** 형태소로 먼저 나눈 뒤 BPE를 적용하는 토크나이저 → 형태소 수준 과제에서 효과적이라고 보고
- **한벗에게:** 감정 분류 과제는 없음 → "표준어 텍스트 분류기의 기본 백본" 정도의 의미

### E4. KOTE · 2024 LREC-COLING

> **한 줄:** 한국어 댓글 하나에 감정 여러 개를 동시에 붙인 대규모 데이터

- **데이터:** 12개 플랫폼(뉴스, 커뮤니티, SNS, 쇼핑, 영상, 영화 리뷰 등) 댓글 **5만 개**
- **어떻게:** 평가자 5명씩 43감정 + 감정없음을 다중 선택 (평가자 총 **3,084명**)
- **결과:** KcELECTRA 미세조정 평균 F1 **0.56** (번역 GoEmotions 학습 모델 **0.41**보다 높음)
- **눈여겨볼 점:** 텍스트 하나당 평균 라벨 **7.91개** → 감정이 하나로 딱 떨어지지 않음 (F 주제와 연결)
- **확인 필요:** 평가자 수를 arXiv 초록은 3,048명으로 표기 🔴

### E5. Choi 외 · 2021 IEEE Access

> **한 줄:** 오타·띄어쓰기가 틀린 문장도 잘 분류하도록 만든 연구

- **문제:** 챗봇 입력의 오타·띄어쓰기 오류 → 형태소 분석이 틀림 → 문장 분류가 망가짐
- **어떻게:** 어절 단위 임베딩 통합 + 학습 데이터에 일부러 노이즈 삽입
- **결과:** 오류 문장 정확도를 크게 올림
- **확인 필요:** 개선 폭이 arXiv 초록(**+17%p**)과 IEEE 판 요약(**+8~15%**)에서 다름 → 원문 대조 필요

### E6. Lee & Shin · 2021 W-NUT

> **한 줄:** 인터넷 말투에 맞춘 한국어 토크나이저(K-MT)를 만든 연구

## E-5. 한벗에 적용하면

1. **기본 경로(Claude)에서는 토큰화·형태소 분석을 하지 않음.**

    - 형태소 분석 후 넣으면 → 오히려 문맥이 깨짐

2. **Claude 감정 출력은 "적은 라벨 + 점수"로 강제함.**
    - 도구 호출(JSON 스키마)의 허용 목록(enum)으로 F의 5감정만 허용
    - 정서가(−2~+2)·각성(1~5)·확신도를 함께 받음

    - 2클래스 긍부정 수준이면 LLM이 미세조정 모델과 거의 같음 (E7)
3. **별도 경량 텍스트 분류기가 필요하면 KcELECTRA를 1순위로 둠.**

    - 토크나이저는 모델에 딸린 것을 그대로 씀
4. **비유창성(머뭇거림)은 지우지 말고 표시만 함.**

    - Claude 입력에는 남기고, 필요하면 `[머뭇거림]` 같은 태그로 정규화
    - **확인 필요:** 이 방식의 효과를 직접 잰 한국어 논문은 찾지 못함 🔴
5. **STT 오류율을 먼저 재야 함.**
    - 텍스트 감정의 상한은 WER이 정함 (E9)
    - 실제 사용자(대학생) 발화에서 RTZR WER이 **12%**를 넘는지 W3 측정 항목에 추가
    - 오류가 크면 → 음성(emotion2vec+) 가중치를 올리는 근거가 됨
6. **학습 데이터를 쓴다면 노이즈 삽입을 함.** 띄어쓰기를 지우거나 STT 오류를 흉내 내는 증강이 오류 입력에 효과적이었음(E5).

# F. 감정 분류 체계

## F-1. 한 줄 결론

**한벗은 "적은 수의 공통 범주 + 정서가·각성 두 축"을 함께 쓰는 혼합 체계가 맞음.**

- 이유 ①: 범주형 라벨은 데이터셋마다 다름
- 이유 ②: 세분할수록 정확도가 떨어짐 → GoEmotions 28클래스 F1 **.46** → Ekman 6분류 **.64** → 감성 4분류 **.69**
- 추천 공통 범주: SER 비교용 4감정(기쁨·슬픔·분노·중립) + 서비스용으로 불안을 더한 5감정

## F-2. 쉬운 개념 설명

감정을 표현하는 방법은 크게 두 가지임.

**① 범주형 (상자에 담기)** — "이 말은 슬픔이다"처럼 이름표를 붙임.
- **Ekman 6 기본 감정**: 기쁨, 슬픔, 분노, 두려움, 혐오, 놀람. 얼굴 표정 연구에서 나왔고, 대부분의 데이터셋이 이 6개에 중립을 더한 7개를 씀(MELD, KEMDy 등).
- **Plutchik 감정 바퀴**: 기본 8감정(기쁨, 신뢰, 두려움, 놀람, 슬픔, 혐오, 분노, 기대)을 바퀴처럼 배치함. 마주 보는 감정은 반대(기쁨↔슬픔)이고, 이웃한 두 감정을 섞으면 복합 감정(dyad)이 됨. 예: 기쁨 + 신뢰 = 사랑, 두려움 + 놀람 = 경외. 강도도 3단계로 나눔(짜증 < 분노 < 격노).
- **GoEmotions 27 + 중립**: 레딧 댓글로 만든 세분 체계. 긍정 감정이 많음(감탄, 감사, 안도 등).
- **KOTE 43 + 감정없음**: 한국어 감정 단어를 군집 분석해서 만든 한국어 맞춤 체계.

**② 차원형 (지도에 점 찍기)** — 감정을 좌표로 나타냄.
- **Russell 원형 모델 (circumplex)**: 가로축 **정서가**(불쾌↔쾌), 세로축 **각성**(차분↔흥분). 모든 감정이 원 둘레에 놓임. 예: 분노 = 불쾌 + 고각성, 외로움 = 불쾌 + 저각성, 편안함 = 쾌 + 저각성.
- **PAD / VAD**: 여기에 **지배성**(상황을 통제하는 느낌)을 세 번째 축으로 더함. 분노(통제감 높음)와 두려움(통제감 낮음)은 정서가·각성이 비슷하지만 지배성에서 갈림.

**③ 혼합형** — 둘 다 붙임.

- 사용 예: IEMOCAP, MSP-Podcast, KEMDy
- 범주 → 해석이 쉬움
- 차원 → "얼마나"와 "범주 사이의 애매한 감정"을 잡음

**왜 한벗에 중요한가?**
- emotion2vec+는 9개, AI Hub는 데이터마다 6~7개, KEMDy는 7개 라벨을 씀 → **그대로는 서로 비교도, 합쳐서 학습도 안 됨.**
- **외로움·쓸쓸함·우울**은 어떤 7·9감정 체계에도 이름이 없음 → 전부 "슬픔"이나 "중립"으로 흡수됨
- 반대로 **편안함·안심**(저각성 긍정)은 "기쁨"이 아니라 "중립"으로 빠지기 쉬움
- → 이 두 가지는 **정서가·각성 축**이 있어야 잡힘

## F-5. 논문별 요약

### F1. Ekman · 1992

> **한 줄:** 문화와 상관없이 얼굴 표정으로 알아보는 기본 감정 6개가 있다는 주장

- **6감정:** 기쁨, 슬픔, 분노, 두려움, 혐오, 놀람 → 이후 감정 데이터셋의 사실상 표준
- **한계:** 긍정 감정이 기쁨 하나뿐 → "편안함, 감사, 그리움" 같은 감정을 못 담음 (GoEmotions가 지적)

### F2. Plutchik · 2001

> **한 줄:** 기본 감정 8개를 바퀴처럼 놓고, 이웃끼리 섞어 복합 감정을 만드는 틀

- **어떻게:** 8개 기본 감정을 바퀴처럼 배치, 중심으로 갈수록 강해짐
- **특징:** 이웃 감정을 섞어 복합 감정을 만드는 개념(dyad)
- **한벗에게:** Claude가 복합 감정을 설명하는 언어로만 쓰면 충분 (예: "그리움 = 슬픔 + 사랑", "서운함 = 슬픔 + 분노")
- **확인 필요:** 정확한 dyad 개수(24개)와 예시는 2차 자료로만 확인함

### F3. Russell · 1980

> **한 줄:** 감정을 "얼마나 불쾌한가 × 얼마나 흥분했나" 두 축의 원 위에 놓는 모델

- **어떻게:** 정서가와 각성 두 축의 원 위에 감정을 배치
- **장점:** 범주 이름 없이도 감정 표현 가능 → 데이터셋 간 라벨이 달라도 공통 좌표로 옮길 수 있음
- **사용 예:** KEMDy·MSP-Podcast·IEMOCAP이 이 축을 함께 라벨링

### F4. GoEmotions · 2020 ACL

> **한 줄:** 감정을 잘게 나눌수록 정확도가 떨어진다는 직접 근거

- **라벨:** 27감정 + 중립
- **결과(같은 BERT):** 27분류 F1 **.46** → Ekman 6그룹 **.64** → 감성 4그룹(긍정·부정·애매·중립) **.69**
- **눈여겨볼 점:** 세분할수록 드문 감정(슬픔·비탄, 안도)이 이웃 감정과 헷갈림 → 성능 하락
- **공식 Ekman 매핑:**
    - 분노 ← 분노·짜증·반대 / 혐오 ← 혐오 / 두려움 ← 두려움·긴장
    - 기쁨 ← 모든 긍정 감정 / 놀람 ← 모든 애매한 감정
    - 슬픔 ← 슬픔·실망·당혹·비탄·후회

### F5. KOTE · 2024

> **한 줄:** 영어 체계를 번역하지 않고 한국어 감정 단어로 직접 만든 43감정 체계

- **어떻게:** 한국어 감정 단어를 fastText 임베딩으로 군집 분석 → 43감정
- **근거:** 문화마다 감정 구조가 다르다는 심리학 연구
- **결과:** 번역 GoEmotions보다 높음 (**0.56** vs 0.41)
- **눈여겨볼 점:** 한 댓글에 평균 **7.91개** 라벨 → 단일 라벨 체계의 한계

### F6. 박인조·민경환 · 2005

> **한 줄:** 한국어 감정 단어 434개를 모아 쾌불쾌·활성화 점수를 매긴 기준 문헌

- **어떻게:** 434개 감정 단어 목록 → 쾌불쾌·활성화 평정 → 유사성 분류를 다차원척도법으로 분석
- **결과:** 쾌–불쾌 축과 타인초점–자기초점 축이 나옴
- **눈여겨볼 점:** **영어 연구와 달리 활성화(각성) 축은 안 나옴**
- **저자가 든 이유:** 단어 선정 기준 차이, 한국어 감정 단어에 극단적 활성화 단어가 적음
- **한벗에게:** 평정 데이터가 CC0로 공개(434단어 × 2개 파일) → 아래 매핑표의 V·A 값에 사용함

### F7. 홍영지 외 · 2016

> **한 줄:** 감정 관련 명사 450개에 정서가·각성·구체성 점수를 매긴 목록

- **대상:** 감정 표현 명사(기쁨)와 감정 유발 명사(천국) **450개**
- **검증:** 정서 스트룹 과제로 타당성 확인
- **눈여겨볼 점:** 박인조·민경환은 형용사·동사 중심, 이 목록은 명사 중심 → 서로 보완

### F8. KNU 한국어 감성사전 · 2018

> **한 줄:** 표준국어대사전 뜻풀이로 만든 긍정/부정 단어 사전

- **규모:** 1-gram, 2-gram, 어구, 문형까지 감성 어휘 **14,843개**
- **참고:** KOTE도 데이터 수집 때 이 사전 단어로 검색함
- **한계:** 범주 감정 없이 긍·부 극성만 있음
- **한벗에게:** LLM 장애 시의 규칙 기반 백업 정도로만 쓸 수 있음

### F9. EmoBox · 2024 Interspeech

> **한 줄:** 여러 나라 감정 음성 데이터를 "모두에게 있는 4감정"만 남겨 비교한 벤치마크

- **만든 곳:** emotion2vec 저자 그룹의 다국어 SER 벤치마크
- **문제:** 데이터셋마다 감정 수가 **3~12개**로 다름
- **어떻게:** 교차 코퍼스 평가는 IEMOCAP·MELD·RAVDESS·SAVEE의 **공통 4감정(분노·기쁨·중립·슬픔)**만 사용
- **표본:** emotion2vec 예측과 원래 라벨이 일치하는 발화만 남겨 감정당 **60개**씩 균형
- **눈여겨볼 점:** 정교한 매핑 규칙 대신 "교집합만 남긴다"는 실용적 방식
- **참고:** 한국어는 포함되지 않음 (기존 노트와 같음)

### F10. SpeechEQ · 2022 Interspeech

> **한 줄:** 라벨이 서로 다른 데이터셋을 "감정 종류 + 강도"로 통일해 함께 학습한 연구

- **어떻게:** "감정 범주 + 강도" 통합 지표로 맞춤 + 음소·성별 인식을 보조 과제로 붙여 학습
- **결과:** 중국어 CASIA·ESD에서 기준선보다 **6.5~8.0%** 높음
- **눈여겨볼 점:** 범주와 강도를 따로 예측하는 설계 → 서로 다른 라벨을 합칠 때 유용

### F11. MSP-Podcast · 2025

> **한 줄:** 자연스러운 실제 대화 감정 데이터(코퍼스)의 최신 정리

- **범주 라벨:** 1차 감정(대표 하나) + 2차 감정(느껴지는 모든 감정)을 따로 받음
- **차원 라벨:** 각성·정서가·지배성을 **1~7점**
- **눈여겨볼 점:** 같은 분노도 "차가운 분노 / 뜨거운 분노"처럼 범주 안 변동이 큼 → 차원 라벨이 함께 필요

## F-6. 한벗에 적용하면 — 추천 체계와 매핑표

### 추천: 2층 혼합 체계

```
[층 1] SER 평가용 4감정  : 기쁨 · 슬픔 · 분노 · 중립   ← 논문 비교용 (EmoBox·IEMOCAP·KEMDy19 4감정과 동일)
[층 2] 서비스 판단용 5감정: 기쁨 · 슬픔 · 분노 · 불안 · 중립  (+ 판정보류)
        + 정서가(쾌–불쾌) · 각성(차분–흥분) 점수   ← 외로움/우울, 편안함을 잡는 축
```

- **4감정을 평가용으로 두는 이유**
    - 기존 한국어 SER 기준선(KEMDy19 4감정 UA **66.3%**)과 EmoBox 교차 코퍼스가 모두 이 4개
    - → emotion2vec+ 결과를 바로 비교할 수 있음
- **불안을 서비스용으로 추가하는 이유**
    - 모든 데이터셋에 두려움·불안 계열이 있음 (emotion2vec+ fearful, AI Hub 불안·두려움, KEMDy 두려움)
    - 다만 SER 단독으로는 불안이 약함 (4감정 평가에서 제외되는 이유) → **텍스트(Claude) 판정 비중을 높게** 둠
- **혐오는 분노로, 당황은 불안으로, 상처는 슬픔으로, 사랑스러움은 기쁨으로 합침.**
    - 아래 표의 한국어 V·A 값이 이 병합을 뒷받침함
    - 혐오·분노: 둘 다 강한 불쾌 + 고각성 / 당황·불안: 불쾌 + 중상 각성 / 서운함: 불쾌 + 저각성
- **놀람·other·unknown은 "판정보류"**로 둠
    - 놀람은 정서가가 중간(**3.11**) → 긍정인지 부정인지 문맥으로만 결정됨
    - → Claude가 텍스트로 정함 (GoEmotions도 놀람을 "애매" 그룹으로 분류)

- 434단어 평균: V **2.37**, A **3.06**
- **확인 필요:** 척도의 정확한 범위는 원문 대조 필요 → **상대 비교용으로만** 써야 함 🔴

### 이 표에서 읽히는 한벗의 핵심 위험

1. **외로움·우울은 "슬픔" 안에서도 각성이 가장 낮음** (A 약 **2.0**)
    - 목소리가 조용하고 단조로움 → SER이 **중립으로 오판**할 가능성이 큼
    - 기존 노트의 "기쁨·분노를 중립으로 놓친다"(KEMDy19 연구)와 같은 방향의 위험
    - → SER이 중립이어도 텍스트 정서가가 낮으면 슬픔 쪽으로 판단하는 규칙이 필요
2. **편안함·안심(쾌·저각성)은 어떤 범주에도 없음.**
    - "요즘 마음이 편해" 같은 긍정 신호가 중립으로 기록됨 → 정서 추이 그래프에서 사라짐
    - → 정서가 점수로만 잡을 수 있음
3. **한국어 감정 단어는 각성 축이 약하게 나타남**
    - 근거: 박인조·민경환 유사성 분석에서 활성화 차원 미출현
    - → 한벗 내부 지표의 1순위는 **정서가**, 각성은 보조로 둠

### 운용 규칙 (제안)

| 상황 | 판단 |
|---|---|
| SER와 텍스트가 같은 공통 감정 | 그대로 채택 |
| SER = 중립, 텍스트 정서가 낮음 | 슬픔(저각성)으로 채택 — 외로움·우울 누락 방지 |
| SER = 분노/불안(고각성), 텍스트 = 중립 | "목소리가 불편해 보임" 가설로 Claude가 확인 질문 |
| SER = other/unknown/surprised | 텍스트 판정만 사용 |
| 텍스트에 위기 단어 | 감정 판정과 무관하게 안전 흐름 우선 (기존 안전 노트 참조) |

- ※ 이 규칙들은 위 논문 결과에서 추론한 설계안 → 규칙 자체의 효과를 검증한 논문은 없음
- W3 측정에서 KEMDy20(텍스트+음성+정서가·각성 라벨이 모두 있음)으로 검증해야 함

## F-7. 확인 필요 항목

- 🔴 **기존 슬라이드의 "4감정 공통표" 구성**을 확인하지 못함. 이 문서는 문헌 표준인 기쁨·슬픔·분노·중립을 가정함.
- 🔴 박인조·민경환 공개 데이터의 평정 척도 범위(0~5 또는 1~5)와 5-level/7-level 파일의 차이(두 파일 크기가 같음).
- 🔴 Plutchik 2001 원문의 dyad 개수·예시 표현(2차 자료로만 확인).
- 🔴 AI Hub 감성대화말뭉치(86) 공식 페이지의 라벨 정의를 직접 확인하지 못함(논문·모델 카드 2차 확인). AI Hub 263·71631 라벨은 기존 데이터셋 노트 기준.
- 🔴 emotion2vec+의 `other`와 `unknown`의 정확한 의미 차이(학습 데이터에서 어떤 라벨이 각각으로 갔는지) 공식 문서 미확인.
- 🔴 한국어 데이터셋 간 라벨 매핑을 실험으로 검증한 논문(예: AI Hub ↔ KEMDy 교차 학습)은 찾지 못함 → 한벗이 첫 사례가 될 수 있음(연구 기여 포인트).
- 🔴 홍영지 외(2016) 참가자 수 불일치(399명 vs 그룹 합 591명).
