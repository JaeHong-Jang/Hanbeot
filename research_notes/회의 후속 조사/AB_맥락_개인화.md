## A. 맥락 반영 감정 인식 (Emotion Recognition in Conversation, ERC)

### 한 줄 결론

- 이전 발화를 같이 보면 감정 인식이 확실히 좋아짐. 단, 효과는 데이터마다 크게 다름
- 대본형 긴 대화(IEMOCAP): 가중 F1(W-F1) **+12.5점** (56.1→68.6)
- 짧은 대화(MELD): **+2점**대에 그침
- 보는 범위(창, window)를 늘리면 **5~12턴에서 포화** → 그 이상은 오히려 떨어지기도 함
- LLM에 맥락을 그냥 많이 넣는다고 좋아지지 않음
  - MELD에서 0→10발화로 늘리면 macro F1 **0.576→약 0.5**로 하락

### 쉬운 개념 설명

- **ERC란?** 앞뒤 대화를 함께 보고 현재 발화의 감정을 맞히는 과제
  - "괜찮아" 한 마디만 들으면 정말 괜찮은 건지 서운한 건지 알 수 없음
  - 바로 앞에 "오늘 아들이 또 전화 안 받았어"가 있었다면 → 해석이 달라짐
- **초기 모델**(DialogueRNN, DialogueGCN): **화자별 상태**를 따로 추적하는 구조
  - 화자별 상태 = 이 사람이 지금 어떤 기분 흐름에 있나
  - 비유: 참여자마다 "감정 일기장"을 하나씩 두고 매 발화마다 갱신하는 방식
- **이후 방식**(EmoBERTa, InstructERC): 과거 대화를 "화자: 발화" 형식으로 그냥 이어 붙임
  - RoBERTa, LLM 같은 큰 언어모델에 입력 → 더 단순하고 성능도 높았음
- **주의할 점**: IEMOCAP은 같은 감정이 연속으로 이어지는 경향("라벨 복사")이 강함
  - → 맥락의 이득이 과장되어 보일 수 있음(Ghosal 2021)
  - 한벗의 실제 대화는 이보다 감정 전환이 잦을 수 있음

### 논문별 요약

### ① DialogueRNN · AAAI 2019

> **한 줄:** 대화에 참여한 사람마다 감정 상태를 따로 기억하는 모델

- **어떻게:** 대화 전체 흐름(전역 GRU) · 화자별 상태(party GRU) · 감정 표현(감정 GRU)을 따로 둠
- **의의:** "화자마다 상태 유지" 발상이 이후 연구의 기준이 됨
- **결과:** IEMOCAP 가중 F1(W-F1) **62.75**로 당시 최고 (CMN 56.13)
- **눈여겨볼 점:** 음성·영상을 더한 멀티모달 버전도 **62.9**로 텍스트와 거의 같음
  - → 맥락이 있으면 음성 정보의 추가 이득이 작음

### ② DialogueGCN · EMNLP 2019

> **한 줄:** 대화를 그래프(점과 선)로 보고 앞뒤 발화를 서로 연결하는 모델

- **어떻게:** 각 발화를 과거 10개 · 미래 10개 발화와 연결
- 화자 간 / 화자 내 관계를 연결선(간선) 종류로 구분
- **결과:** IEMOCAP **64.18**, MELD **58.10** → DialogueRNN을 넘음
- **눈여겨볼 점:** 실험 기본 창이 10 → "몇 턴을 볼까"의 한 기준

### ③ COSMIC · Findings of EMNLP 2020

> **한 줄:** 상식 추론으로 "왜 이 말을 했을까"까지 따져 감정을 맞히는 모델

- **어떻게:** 상식 추론 모델(COMET)로 두 가지를 뽑아 넣음
  - 화자가 왜 이 말을 했는지 / 상대는 어떻게 느낄지
- **결과:** IEMOCAP **65.28**, MELD **65.21**
- **한벗에게:** LLM 시대에는 Claude가 이 상식 추론을 자체적으로 할 수 있음
  - → 별도 모듈보다 프롬프트로 대체하는 쪽이 현실적

### ④ EmoBERTa · arXiv 2021

> **한 줄:** 앞뒤 대화를 "누가: 무슨 말" 형태로 이어 붙이기만 한 단순한 방법

- **어떻게:** 구조 변경 없이 RoBERTa 입력에 과거/미래 발화를 512토큰까지 채움
  - 형식: "JOEY: 발화"
- **결과:** IEMOCAP 맥락 없음 56.09 → 과거 발화만 넣어도 68.57 (**+12.48점**)
- MELD는 **+2.15점**에 그침 (저자: IEMOCAP이 더 맥락 의존적)
- **눈여겨볼 점:** 화자명을 빼면 IEMOCAP **64.02**로 하락 → **누가 말했는지 표시**가 중요
- **확인 필요:** 동료 심사 학회 게재는 확인 못 함

### ⑤ Ghosal 외 맥락 실험 연구 · Findings of ACL 2021

> **한 줄:** 맥락을 일부러 망가뜨려 보며 맥락이 얼마나 중요한지 잰 실험 연구

- **어떻게:** 맥락을 망가뜨리고 성능 변화를 봄
  - 섞기, 과거 5개 제거, 과거 전부 제거, 5개만 남기기 등
- **결과:** 섞기만 해도 모든 과제에서 수 점 하락
- IEMOCAP 감정은 먼 맥락까지 중요 / 설득 대화 등 다른 과제는 **5발화 창이면 충분**
- **눈여겨볼 점:** 학습은 과거로, 추론은 미래로 하는 식으로 맥락 조건이 어긋나면 → **성능이 크게 무너짐**
- **주의:** IEMOCAP은 연속 발화의 감정이 같은 경우가 많음(라벨 복사)
  - → 맥락 이득이 데이터 특성 때문일 수 있다고 지적

### ⑥ InstructERC · arXiv 2023~2024

> **한 줄:** 감정 인식을 LLM이 답을 써내는 문제로 바꾸고, 몇 턴을 볼지 실험한 연구

- **어떻게:** 지시문 + 과거 w턴 대화 + 검색한 유사 예시 + 보조과제(화자 식별·감정 영향 예측)
- Llama2-7B를 LoRA로 미세조정
- **결과:** IEMOCAP **71.39**, MELD **69.15**, EmoryNLP **41.37**로 당시 최고
- **창 크기:** 1턴 56.12 → 12턴 71.39 (**15점 이상 차이**) → 20턴 71.01로 소폭 하락
- **저자 정리:** "RoBERTa급 모델은 5턴이 한계였는데 LLM은 더 볼 수 있음, 그러나 어느 지점부터는 더해도 좋아지지 않음"

### ⑦ Wang·Feng·Narayanan · arXiv 2025

> **한 줄:** 미세조정 없이 LLM에 맥락을 길게 주면 어떻게 되는지 본 연구

- **어떻게:** LLM(Llama-3.1-8B)에 예시를 보여주는 방식(in-context learning), 미세조정 없음
- **결과(IEMOCAP):** 맥락 0→5→10발화에 **0.465→0.536→약 0.567**로 상승
- **결과(MELD·EmoryNLP):** 맥락이 없을 때가 가장 좋음 → 10발화에서 **약 0.5**로 하락
- **눈여겨볼 점:** 프롬프트 기반 LLM은 맥락이 길면 → **현재 발화에 대한 집중이 흐려질 수 있음**
- **확인 필요:** 15·20발화 값은 그림에만 있어 수치 확인 필요

### ⑧ KD-EmoR · IEEE Access 2022

> **한 줄:** 한국 TV 드라마 대본으로 만든 한국어 텍스트 대화 감정 데이터

- **어떻게:** 감정을 3분류로 묶음 → 긍정적 흥분(euphoria) · 불쾌(dysphoria) · 중립
- 화자 수준 · 장면 수준 맥락을 쓰는 모델
- **결과:** F1 **0.63**
- **눈여겨볼 점:** 한국어 ERC 공개 자원이 드물다는 점을 보여주는 사례
- **확인 필요:** 데이터 크기는 초록에서 확인 못 함

### 한벗에 적용하면

1. **감정 판단에 넘길 맥락: "직전 사용자·한벗 발화 합쳐 6~10턴"부터 시작**
   - 5발화 창이면 대체로 충분(⑤)
   - LLM 미세조정 기준 5턴 **68.65** vs 12턴 **71.39** → 차이 2.7점(⑥)
   - 미세조정 없는 LLM은 길수록 오히려 나빠질 수 있음(⑦)
   - 한벗은 Claude를 미세조정 없이 씀 → ⑦의 상황에 가까움
   - 처음부터 전체 대화를 넣지 말 것
2. **화자 표시를 반드시 붙임**
   - "사용자:", "한벗:" 형식
   - 근거: ④에서 화자명 제거 시 **4.5점** 하락
3. **감정 판단과 응답 생성을 프롬프트상 분리**
   - 현재 발화를 마지막에 둠
   - "직전 대화는 참고용, 판단 대상은 마지막 사용자 발화"로 명시
   - 이유: ⑦에서 맥락이 현재 발화 판단을 흐린 문제를 줄이기 위함
4. **SER(emotion2vec+) 결과도 턴별로 붙여서 넘김**
   - 예: `사용자(음성 추정: 슬픔 0.62): ...`
   - 단발 SER은 약함(기존 노트: 한국어 4감정 UA 약 66%)
   - 여러 턴의 추정 흐름을 LLM이 보면 → 한 번의 오판 영향이 줄어듦
   - 맥락이 있으면 음성 단독 이득은 작음(① 62.75→62.9) → SER은 "보조 신호"로 유지
5. **평가도 같은 조건으로**
   - 학습·평가 때와 서비스 때 맥락 길이가 다르면 → 성능이 무너짐(⑤)
   - W3 측정 시 "맥락 0턴 / 2턴 / 6턴 / 10턴"으로 나눠 재보는 실험 권장
   - KEMDy20은 대화 데이터라 이 실험에 바로 쓸 수 있음
6. **IEMOCAP 수치(+12점)를 그대로 기대하지 말 것**
   - 라벨 복사 효과가 섞여 있음(⑤)
   - 현실적 기대치는 MELD 쪽(+2~3점)과 IEMOCAP 사이로 보는 게 안전

### 확인 필요 항목

- InstructERC 표의 ChatGPT-3.5 zero-shot 수치: PDF 표가 깨져 정확한 대응 확인 못 함. 동료 심사 게재처도 확인 못 함.
- EmoBERTa 동료 심사 게재 여부.
- ⑦의 15·20발화 macro F1(그림에만 있음).
- KD-EmoR 데이터 크기와 발화 수.

## B. 개인화 감정 인식 (Speaker-adaptive / Personalized SER)

### 한 줄 결론

- 사람마다 "평소 목소리"가 다름 → 그 사람의 기준선에 맞춰 보정하면 감정 인식이 좋아짐
- **정서가(긍정/부정)** 예측은 개인차가 커서 개인화 이득이 큼
  - 일치도(CCC) 상대 **+13.5%** vs 각성·지배는 +1~2%
- 사용자별 예시 1~7개를 보여주는 방식 → 일본어 7감정에서 화자별 UA **0.675→0.757**(+8.2점)
- 경우에 따라 평균 성능은 거의 그대로
  - 대신 **가장 못 맞히는 사람을 끌어올리는 효과**(공정성)가 더 뚜렷

### 쉬운 개념 설명

- **왜 필요한가:** 원래 목소리가 낮고 느린 할머니 → 일반 모델은 매번 "슬픔·피곤"으로 볼 수 있음
  - 이건 감정이 아니라 **그 사람의 평소 상태**임
  - 비유: 평소 체온이 35.8도인 사람에게 36.8도는 이미 미열인 것과 같음
- **개인화 방법 세 가지**
  1. **기준선 정규화**: 그 사람의 중립 발화로 평균·분산을 구해 특징을 보정(Busso IFN)
  2. **비슷한 화자 찾아 적응**: 학습 데이터에서 목소리가 비슷한 사람들을 골라 모델을 다시 맞춤(Sridhar & Busso, Tran 외)
  3. **등록(enrollment) 예시 사용**: 그 사람의 감정별 예시 몇 개를 모델에 함께 보여줌(Triantafyllopoulos 외, Ihori 외)
- **기억형 동반자(companion)** 쪽의 개인화: "그 사람에 대한 사실·선호를 기억해서 대화에 반영"하는 형태(B-2 참고)

### 논문별 요약

### ⑨ Busso 외 IFN · ICASSP 2011 / IEEE TAC 2013

> **한 줄:** 그 사람의 "평소(중립) 목소리"를 기준으로 특징을 보정하는 방법

- **문제:** 사람마다 음높이·에너지 기본값이 달라 감정 판단이 흔들림
- **어떻게:** 화자별로 "중립처럼 보이는 발화"를 골라 그것만으로 정규화
  - → 감정 판정을 다시 해서 중립 집합을 갱신 → 이 과정을 반복
- **결과:** 정규화를 안 하거나 전체 평균으로 하는 것보다 좋음
- **확인 필요:** 후속 연구의 69.8→71.8% 수치는 검색 요약에서 본 것이라 과제·지표 확인 필요

### ⑩ Sridhar & Busso · IEEE TAC 2022

> **한 줄:** 라벨 없이, 목소리가 비슷한 다른 사람들 데이터로 모델을 그 사람에게 맞춤

- **출발점:** 정서가(긍정/부정)는 각성보다 개인차가 큰 신호 → 일반 모델 성능이 낮음
- **어떻게:** 시험 화자의 음성 200초로 학습 데이터 중 비슷한 화자 5명을 찾음
  - → 그들 데이터를 가중해 사전학습 모델을 다시 맞춤
- **결과:** 정서가 일치도(CCC) **0.308→0.350** (상대 **+13.5%**)
  - 각성(+1.8%)·지배(+1.2%)보다 훨씬 큰 이득
- **눈여겨볼 점:** 라벨이 전혀 필요 없음

### ⑪ Tran 외 PAPT · Interspeech 2023

> **한 줄:** 화자 정보를 넣어 사전학습하고, 비슷한 화자 기준으로 치우침을 보정하는 방법

- **어떻게:** 화자별 학습 가능한 임베딩을 넣어 음성 인코더를 사전학습
  - 비슷한 학습 화자의 라벨 분포로 시험 화자의 치우침을 보정
- **결과(MSP-Podcast):** 정서가 CCC **0.607→0.663**, 각성 **0.712→0.740**
- **눈여겨볼 점:** 역시 정서가 쪽 이득이 더 큼
- **확인 필요:** 몇 개의 시험 화자 샘플로 적응했는지는 본문에 명시 없음

### ⑫ Gat 외 · ICASSP 2022

> **한 줄:** 반대로, 음성 특징에서 "누가 말했는지" 정보를 지워 버리는 접근

- **어떻게:** 특징에서 화자 정보를 적대 학습으로 지움 → "누가 말하든 같은 감정은 같게"
- **결과:** IEMOCAP에서 최고 성능(SOTA)을 주장
- **확인 필요:** 초록에 수치 없음
- **한벗에게:** emotion2vec+를 그대로 쓰므로 직접 적용보다는 문제 인식의 근거로 쓸 만함
  - "화자 정보가 감정 판단을 오염시킨다"

### ⑬ Triantafyllopoulos 외 · 2024

> **한 줄:** 감정별 예시를 하나씩 등록해, 잘 안 맞던 사람의 정확도를 끌어올림

- **어떻게:** 감정별 등록 발화 1개씩을 같이 넣는 구조
- **결과(MSP-Podcast):** 전체 UAR은 사실상 변화 없음
  - 하지만 화자별 평균 UAR **.438→.479**, 화자 간 불평등도 줄어듦
- **결과(FAU-AIBO 5분류):** 최저 화자의 UAR **.053→.189**로 크게 오름
- **눈여겨볼 점:** 평균 지표만 보면 → 개인화 효과를 놓칠 수 있음

### ⑭ Ihori 외 NTT · 2025

> **한 줄:** 사용자 예시 몇 개만 보고 그 사람에게 맞추도록 학습한 음성-언어 모델

- **어떻게:** 음성-언어 모델을 "몇 개 예시를 보고 그 사람에게 맞추는 법"으로 메타 학습
- **결과(일본어 800명 7감정):** 예시 1개 **0.698** → 3개 **0.732** → 7개 **0.757**
  - 3개 이후로는 증가폭이 작아짐
- **눈여겨볼 점:** 중립 발화만 등록(0.595) < 전 감정 등록(0.626) → **중립 기준선만으로는 한계**
- **단,** 0-shot에서는 기본 음성 LM(0.675)보다 약간 낮음(0.664)

### ⑮ Bae 외 Keep Me Updated! · Findings of EMNLP 2022

> **한 줄:** 한국어 돌봄 전화에서, 사용자 기억을 쌓기만 하지 않고 고쳐 가며 관리하는 방법

- **데이터:** 네이버 CareCall(돌봄 안부 전화) 한국어 대화 **7,665세션**
- **어떻게:** 세션이 끝나면 사용자 정보를 요약 문장으로 저장
  - → 새 정보와 비교해 유지·교체·추가·삭제를 결정
  - 분포: 추가 44.6%, 교체 37.0%, 유지 13.3%, 삭제 5.1%
- **결과(사람 평가 기억도):** 갱신 **56.59** > 누적 50.31 > 기억 없음 36.37
- **눈여겨볼 점:** 5세션째 누적 방식 기억도가 음수(**-0.67**)
  - → **오래된 정보가 쌓이면 오히려 해가 됨**
- **참고:** 논문 윤리 절에서 이용자를 취약 집단으로 언급
- **확인 필요:** CareCall의 정확한 대상 연령은 본문에서 확인 못 함

### ⑯ Beyond Goldfish Memory · ACL 2022

> **한 줄:** 여러 번에 걸친 대화를 기억하는지 재는 데이터(MSC)를 처음 공개한 연구

- **어떻게:** 여러 세션에 걸친 사람-사람 대화 데이터(MSC) 공개
- **결과:** 기존 모델은 긴 기간 대화에서 성능이 낮음
  - 과거 대화를 요약해 저장 → 검색해 쓰는 방식이 더 좋았음
- **눈여겨볼 점:** 이후 MemGPT 등 대부분의 장기 기억 연구가 이 데이터로 평가

### ⑰ MemoryBank · 2023

> **한 줄:** 사람처럼 시간이 지나면 잊고, 다시 언급되면 강해지는 기억 장치

- **어떻게:** 기억을 저장·검색·갱신 + 에빙하우스 망각 곡선을 본뜸
  - 시간이 지나고 덜 중요한 기억은 약해짐 / 다시 언급되면 강화
  - 사용자 성격도 요약해 둠
- **적용:** 동반자 챗봇 SiliconFriend
- **확인 필요:** 초록에 정량 수치가 없어 효과 크기 확인 필요

### ⑱ MemGPT · 2023

> **한 줄:** 컴퓨터 메모리처럼, 필요한 기억만 꺼내 쓰고 나머지는 따로 보관하는 LLM

- **어떻게:** LLM의 문맥 창을 컴퓨터의 메모리처럼 봄
  - 당장 필요한 것만 문맥에 둠
  - 나머지는 외부 저장소에 넣었다가 필요할 때 함수 호출로 불러옴
- **결과(MSC 과거 세션 사실 회상):** GPT-4 단독 **32.1%** → MemGPT **92.5%**
- **눈여겨볼 점:** 기억 관리 자체를 하나의 전담 루프로 분리한 설계

### ⑲ LoCoMo · ACL 2024

> **한 줄:** 수십 번에 걸친 아주 긴 대화를 얼마나 잘 기억하는지 재는 시험

- **어떻게:** 수백 턴, 수십 세션의 초장기 대화로 기억을 평가
- **결과(F1):** 사람 **87.9** vs 긴 문맥 GPT-3.5-16K **37.8**, 최고 검색 증강(RAG) **41.4**
- **눈여겨볼 점:** RAG 중에서는 원문 대화보다 **대화에서 뽑은 관찰 문장(observation)을 검색**할 때 가장 좋음
  - → 긴 문맥을 그냥 넣는 것도, 원문을 검색하는 것도 해답이 아님

### ⑳ Lost in the Middle · TACL 2024

> **한 줄:** 긴 입력의 가운데에 있는 정보를 LLM이 잘 놓친다는 연구

- **결과:** 정보가 처음·끝에 있으면 잘 씀 / **가운데 있으면 크게 하락**(U자형)
- 긴 문맥을 지원하는 모델도 마찬가지
- **눈여겨볼 점:** 전체 대화를 다 넣는 방식의 근본적 약점

### 한벗에 적용하면

1. **사용자별 감정 기준선을 pgvector/Postgres에 저장**
   - **수집 기간:** 첫 1~2주(또는 첫 N회 통화)는 "기준선 수집 기간"으로 둠
   - 사용자 발화의 emotion2vec+ 임베딩·감정 확률·피치·에너지 등 통계를 쌓음
   - **테이블 예:** `user_affect_baseline(user_id, feature_name, mean, std, n_samples, updated_at)`
   - 여기에 pgvector 열 `neutral_centroid vector(768)` 추가 (emotion2vec+ 임베딩 차원은 실제 모델 출력 차원 확인 필요)
   - **해석:** 원점수 대신 **기준선 대비 편차(z-score) 또는 중립 중심과의 거리**로 봄(⑨의 원리)
   - LLM에는 "평소보다 슬픔 확률이 2표준편차 높음" 같은 형태로 전달
   - **중립 판정:** IFN처럼 반복 갱신
   - 단 ⑭에서 중립만 등록하면 이득이 작았음 → 감정별 예시도 조금씩 모음
   - 방법: 사용자가 "응, 오늘 좀 속상했어"처럼 **확인 질문에 답한 발화를 라벨 있는 등록 예시로 저장**
   - 감정별 1~3개면 ⑬⑭의 이득 대부분
2. **정서가(긍정/부정) 판단을 개인화의 1순위로**
   - 개인차가 가장 크고 개인화 이득도 가장 큼(⑩ +13.5%, ⑪ +0.056 CCC)
   - 각성(흥분/차분)은 일반 모델로도 비교적 안정적
3. **평가는 평균보다 "가장 안 맞는 사용자" 기준으로**
   - ⑬처럼 전체 정확도는 그대로여도 최저 사용자의 성능이 크게 오를 수 있음
   - 노인·사투리 화자는 학습 데이터에 적은 소수 화자 → 이 효과가 특히 중요
4. **개인화는 원본 음성이 아니라 임베딩·통계만 보관**
   - 기존 노트(safety_privacy)의 "원본 음성 즉시 폐기" 원칙과 충돌하지 않음
   - 다만 임베딩도 화자 식별에 쓰일 수 있음 → 사용자 삭제 요청 시 함께 삭제

### 확인 필요 항목

- ⑨ Rahman & Busso 2012의 69.8/71.8/72.8% 수치의 과제·지표(검색 요약에서만 확인).
- ⑫ Gat 외 IEMOCAP 구체 수치.
- ⑬ 게재 학회(Interspeech 2024 여부)와 전체 저자 목록.
- ⑰ MemoryBank의 AAAI 2024 게재 여부와 정량 결과.
- ⑮ CareCall 서비스의 대상(1인 가구·노인 여부) 원문 확인.
- ⑯ MSC 본문 수치.
- **노인 화자 대상 개인화 SER 연구, 한국어 개인화 SER(KCI)**: 이번 조사에서 찾지 못함. KAIST 학위논문 "다계층 자료 선택 기법을 이용한 화자 적응 기반의 음성 감정 인식"(https://dspace.kaist.ac.kr/handle/10203/34993) 이 제목상 가장 가깝지만 초록·수치 미확인.
- 노인 대상 LLM 동반자의 기억 기능 효과: 등록된 RCT(ClinicalTrials.gov NCT07822828, 72명 목표, 세션 간 기억 있는 LLM vs 규칙 기반)가 있으나 결과 미발표. 나머지는 n=7 등 소규모 탐색 연구뿐.

## 회의 질문: "앞 2~3턴만 보낼지 vs 전체 대화를 저장할지, 저장 전담 에이전트를 두는 게 나은지"

### 결론

**둘 중 하나가 아니라 "3층 구조"가 논문들의 공통 결론임.**

1. **감정 판단:** 짧은 최근 창
2. **대화 원문:** DB에 전부 저장하되 LLM에는 넣지 않음
3. **세션 요약·사용자 사실:** 별도 기억으로 관리하고 필요할 때 검색

→ 그리고 3번은 **응답 생성과 분리된 전담 단계(에이전트)**로 두는 게 근거가 가장 강함.

### 근거

| 질문 | 근거 | 숫자 |
|---|---|---|
| 감정 판단에 몇 턴? | ⑤ 5발화 창이면 대체로 충분 / ⑥ 5턴→12턴 +2.7점, 20턴은 하락 / ⑦ 미세조정 없는 LLM은 맥락 늘리면 MELD에서 하락 | ⑥ IEMOCAP 68.65(5턴)→71.39(12턴)→71.01(20턴). ⑦ MELD 0.576(0)→약 0.5(10) |
| 2~3턴이면 부족한가? | ⑥에서 1턴은 56.12로 5턴보다 12.5점 낮음. Jeong 2023(기존 노트, KEMDy20)은 2발화 맥락 단독 F1 +0.7, 음성 결합 시 +5.7 | 2~3턴은 "최소선", 6~10턴이 안전한 기본값 |
| 전체 대화를 다 넣으면? | ⑳ 가운데 정보 손실 / ⑲ 긴 문맥 모델 F1 37.8 vs 사람 87.9 / ⑱ GPT-4 단독 회상 32.1% | 전체 투입은 비용도 크고 정확하지도 않음 |
| 그럼 저장은? | ⑱ 기억 계층 분리 시 32.1→92.5% / ⑲ 원문보다 관찰 요약 검색이 최고(41.4) / ⑯ 요약+검색이 우수 | 원문 저장 + 요약 검색이 정답 |
| 쌓기만 하면? | ⑮ 누적만 하면 5세션째 기억도 -0.67, 갱신하면 +0.24. 기억도 50.31 vs 56.59 | **갱신(교체·삭제)하는 관리자가 필요** |
| 전담 에이전트? | ⑱ MemGPT가 기억 관리를 별도 루프로 분리, ⑮ 기억 연산(유지/교체/추가/삭제)을 별도 분류기로 수행 | 응답 생성과 분리된 기억 관리 단계가 성능 차이의 핵심 |

### 한벗 설계 제안

```
[실시간 턴 경로 · 지연 민감]
  최근 창: 직전 6~10턴(사용자/한벗 화자 표시 + 턴별 SER 추정·기준선 대비 편차)
  + 검색된 기억 3~5개(pgvector, 현재 발화와 유사도 기준)
  + 사용자 프로필 요약 1단락(이름, 가족, 건강, 선호, 최근 주요 사건)
  → Claude 응답 생성
  ※ 중요한 정보는 프롬프트 처음(프로필)과 끝(현재 발화)에 배치 (⑳)

[비동기 기억 경로 · 통화 종료 후 또는 N턴마다]
  기억 관리 에이전트(작은 모델로도 가능):
   1) 세션 요약 → "관찰 문장" 단위로 추출 (⑲)
   2) 기존 기억과 비교해 PASS / REPLACE / APPEND / DELETE 결정 (⑮)
   3) 사용자 감정 기준선 통계 갱신 (B-1 제안)
   4) 중요도·최근성 점수 부여, 오래되고 안 쓰인 기억은 가중치 하향 (⑰)

[저장소]
  conversation_raw   : 전사 원문 전체 (LLM에 직접 안 넣음, 감사·재요약용, 보존기간 정책 필요)
  memory_items       : 관찰 문장 + embedding + importance + last_used + status
  user_profile       : 요약 1단락 (기억 에이전트가 갱신)
  user_affect_baseline: 감정 기준선 통계 + 등록 예시
```

- **"앞 2~3턴만"은 감정 판단엔 다소 짧고, 장기 기억 대체로는 불가능함.**
  - 2~3턴은 최소선 → 6~10턴을 기본으로 함
  - 비용·지연을 보며 줄이는 실험(0/2/6/10턴)을 W3에 포함할 것
- **전담 에이전트는 실시간 경로 밖에 둘 것.**
  - 음성 대화는 지연에 민감 → 기억 정리는 통화 후 비동기로 처리해 응답 지연을 늘리지 않음
  - 기존 노트의 "저장 전 사용자 승인" 설계(CHI '26 AI Never Forgets)와도 잘 맞음
  - → 기억 에이전트가 만든 후보를 사용자에게 보여주고 승인받는 단계를 넣기 쉬움
- **확인 필요:** 한국어 노인 대화에서 최적 창 크기, 기억 에이전트 유무에 따른 사용자 만족도 차이는 직접 측정한 연구를 찾지 못함
  - ⑮(CareCall, 한국어)가 가장 가까운 근거
