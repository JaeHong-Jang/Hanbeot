# 한벗 기술 논문 근거

이 문서는 한벗 앱 설계서(`reports/한벗 앱 설계서.md`) 5절의 기술 선택마다 어떤 논문이 근거인지 정리하고, 교수님 1차 피드백 ①②⑤에 논문 근거로 답한다. 작성일은 2026-10-26이다. 입력은 리서치 노트 3건과 검증표 3건이며, 노트와 검증표가 다르면 검증표를 따랐다. 검증표는 같은 GPT 계열 검증자 한 명의 판정이라 독립 재현은 아니다. 주장별 원문 위치·확인 방법·판정 이유는 검증표 파일(`.omc/orchestra/reviews/20261026_130317_verify_speech_pipeline_papers.md`, `20261026_130842_verify_ser_limits_papers.md`, `20261026_131507_verify_safety_privacy_hci_papers.md`)의 "확인 방법"·"메모" 열에 있다. 등급은 출처 일치도이며 연구의 질이나 한벗 적용 가능성 평가가 아니다. 등급 범례: **A**는 원출처에서 수치·서술을 직접 확인한 것, **B**는 2차 출처·근사치·조건부 확인이다. **C(미확인·불일치)는 본문 표에 사실로 쓰지 않고 4절에 따로 모았다.** A는 출처와 일치한다는 뜻이지 한벗에서의 효과나 안전성을 보증하지 않는다. 검증 통계(주장 단위): 음성 파이프라인 A51/B5/C32, SER 한계 A57/B24/C37, 안전·개인정보·HCI A70/B5/C29. 논문 번호 [P#]는 6절 목록과 설계서 10.1.1절이 같다. 2026-10-26 비평 반영 내역은 7절에 있다.

## 0. 한 장 요약

1. **VAD = Silero** → [P1][P2] → 영어 실환경 비교에서 Silero가 WebRTC·RMS보다 우수(P1, 수치는 초록에 없음). 잡음 혼합 0 dB에서 FPR 5%일 때 TPR Silero 87.7%, WebRTC 50%(P2) → 둘 다 영어이고 P2는 벤더 자체 평가다. 한국어·모바일 소음 수치는 없다.
2. **턴 감지 = Smart Turn v3** → [P6] → 한국어 정확도 96.85%(n=890), False Positives 1.12%, False Negatives 2.02%. CPU 12.6~94.8ms(전처리 포함) → 벤더 자체 테스트셋이다. 한국어 고민 발화의 조기 종료율은 W2에 직접 잰다.
3. **끼어들기 기본 ON, 백채널에 끊지 않음** → [P13][P14] → 끼어들기 후 응답 지연 Moshi 0.257s, Gemini Live 1.183s(P13 v3). 오디오 모델은 과도하게 끼어들고 백채널을 거의 안 낸다(P14) → 영어 평가다. 백채널 "예측" 연구(P11)는 들어온 "응/음"을 판별하는 과제와 다르므로 W2에 실제 겹친 발화로 따로 잰다.
4. **TTFA P50 ≤ 1.0s** → [P15][P16][P18] → 사람의 턴 간격은 약 200ms(P16). 언어별 평균은 교차언어 평균과 ±250ms 안팎 차이(P15, 한국어 포함, 개별 대화의 변동 범위가 아님). ChatGPT Voice 평균 약 1,370ms(P18, 측정 조건 다름) → 다른 수치는 참고 맥락이다. 한벗은 설계서 7.2 정의로 P50·P95를 직접 잰다. "달성 불가"라고 쓰지 않는다.
5. **STT = RTZR, CER 목표 ≤ 8%** → [P3][P4] → Whisper large-v2 zero-shot KsponSpeech eval-clean CER 14.66%, 미세조정 후 10.48%(P3 v3) → RTZR의 독립 학술 검증은 없다. 8%는 팀 녹음으로 확인한다.
6. **SER = emotion2vec+, 합격선 UA ≥ 0.70** → [P20][P21][P26] → 원 논문들은 한국어를 평가하지 않았다. 다른 모델의 일반화 실패 사례로, 미관측 코퍼스에서 macro-F1이 0.67~0.78에서 0.13~0.20으로 떨어졌다(P21, B, emotion2vec+ 미포함) → 한국어 성능은 W3 자체 벤치마크 전까지 모른다.
7. **SER 점수 0.6 이상일 때만 확인 질문** → [P39][P31] → 저신뢰 거부 전략은 모델 보정을 전제한다(P39). 특정 영어 전화 대화 데이터에서 Emotion2Vec 분노 F1 0.000(P31) → 0.6은 보정 검증 전에는 확률로 해석하지 않으며, 임계값 선택용 세트와 최종 평가 세트를 분리한다. 분노("답답함") 질문은 질문 정밀도 확인 전까지 보류를 권한다.
8. **위기 2단 분류 + 109 카드** → [P73][P74][P70] → LLM 챗봇의 직접 답변 정책은 중간 위험 질문에서 일관되지 않았다(P73, 응답 정책 연구이며 탐지 성능 근거가 아님). 범용 음성비서의 위기 질문 응답은 비일관적이었다(P74). 한국어 분류는 게시글 기반 F1 0.88(이진)·0.72(4단계)뿐(P70) → 2단 구조의 효과는 키워드 단독·태그 단독·결합 비교와 STT 포함 전체 경로 평가로 직접 확인한다.
9. **저장 전 승인·원본 음성 미저장** → [P65][P67][P83][P85] → 연구 참가자 20명 대부분이 저장된 기억을 보고 부정적 기대 위반(P65). 80명의 메모리 2,050건 중 96%가 시스템 주도 생성(P67, 동의 부재의 증명은 아님). 정신건강 앱 33/36이 실제 제3자 전송(P83). 음성 화자 비교 실험에서는 탐색 공간이 커질수록 재식별이 어려워졌다(P85) → 원본 미저장은 데이터 최소화 설계 판단이다.
10. **사용 시간 알림** → [P90] → 4주 RCT 981명에서 자발적 고사용은 외로움·의존 증가와 **관련**(인과 아님) → 60분 기준은 임시 운영 기준으로 유지하고 효과를 주장하지 않는다.

## 0.1 기술 성능 → 사용자 가치 가설

새 가설을 만들지 않고 설계서 0.1.1의 H1~H5에 연결만 한다. 기술 성능이 기준을 넘어도 사용자 가치가 확인되지 않으면 오른쪽 조치를 따른다.

| 기술 성능(이 문서) | 사용자 가치로 이어진다는 가설 | 설계서 가설 | 측정(설계서) | 가치가 확인되지 않을 때(설계서 반증 시 조치) |
|---|---|---|---|---|
| 통화 루프 전체(음성·기억·안전) | 고민을 털어놓을 상대·시간이 없는 상황이 실제로 있다 | H1 | 인터뷰 8~10명, W6 사전 설문 | 타깃 상황 재정의, 범위 축소(8.3) |
| TTFA·끼어들기·STT 품질(①②③⑦) | 음성 대화가 텍스트보다 선택될 만큼 자연스럽다 | H2 | 사후 설문, 인터뷰 | 텍스트 우선 + 음성 보조로 재설계 |
| SER 확인 질문(④⑤) | 음성 단서 기반 질문이 일반 질문보다 "이해받음"을 높이고 침해감은 낮다 | H3 | W6 비교(2절 ① 실험 설계) | SER·확인 질문 P2 강등 |
| 4상태 기억·저장 전 승인(⑧) | 승인을 귀찮아하지 않고 기억 사용을 가치로 본다 | H4 | 후보 처리율 로그, 설문 2문항 | 통화별 저장 ON/OFF + 사후 삭제로 단순화 |
| 분당 원가(STT·TTS·Claude, 7.1) | 지불 의사가 이용량별 원가를 넘는다 | H5 | 가격 문항, 모의 플랜, 7.3 손익 | 가격·무료 분 상한 재설계 |

SER·메모리 prefetch의 세션당 추가 비용(서버 연산)은 설계서 7.1에 없다. W3 실측 후 7.3 손익에 넣고, H3·H4가 반증되면 해당 기능의 비용을 없앤다.

### ① 음성 감정 분석의 정확도·한계 검증 계획과 오추정 위험

**(a) 교수님 질문**: "음성 감정 분석의 정확도와 한계를 어떻게 검증할지 계획이 없습니다. 감정 추정이 틀릴 경우 사용자에게 어떤 영향을 줄지도 위험으로 다뤄야 합니다."

**(b) 답변 초안**

한벗은 음성 감정 분석(SER)을 판정이 아니라 확인 질문의 계기로만 씁니다. 한국어 정확도는 현재 문헌으로 보장할 수 없습니다. 이번 조사에서 확인한 emotion2vec 원 논문, SER Evals, EmoBox는 한국어를 평가하지 않았고, emotion2vec+의 한국어 공개 평가는 찾지 못했습니다 [P20][P21][P22]. 다른 모델의 일반화 실패 사례로, 13개 언어 벤치마크에서 학습에 쓰지 않은 코퍼스로 옮기면 모델별 평균 macro-F1이 약 0.67~0.78에서 0.13~0.20으로 떨어졌습니다 [P21]. 이 표에 emotion2vec+는 없으므로 우리 모델의 예상 성능은 아닙니다. 한국어 공개 수치로는 AI Hub 4-class 정확도 0.8139가 있으나, 지표가 UA가 아니고 화자 독립 여부도 확인되지 않아 합격선(UA 0.70)과 직접 비교하지 않습니다 [P26]. 자연 대화는 더 어렵습니다. 한 영어 전화 대화 데이터에서 사람 평가자 간 주 감정 합의도는 Krippendorff α 0.25였고, IEMOCAP 라벨로 미세조정한 Emotion2Vec의 분노 F1은 0.000이었습니다 [P31]. 통화 코덱도 변수여서, Opus를 포함한 코덱 재합성에서 SER 성능이 떨어졌습니다 [P34]. 모델 점수는 보정 검증 전에는 확률로 해석하지 않으며, 임계값을 고르는 세트와 최종 평가 세트를 화자 단위로 나눕니다 [P39]. 오추정 위험으로는 불완전한 추정에 근거한 단정적 공감이 반감을 부를 수 있다는 문제 제기가 있습니다 [P43]. 확인 질문이 이 피해를 줄인다는 직접 연구는 찾지 못했으므로, W3 한국어 벤치마크와 W6 비교 실험(음성 단서 기반 확인 질문 대 같은 빈도의 일반 확인 질문)으로 직접 검증하고, 합격선 미달 시 SER을 후순위로 내립니다.

### ② 위기 상황 대응 흐름과 전문 기관 안내 방식

**(a) 교수님 질문**: "정신건강과 관련된 서비스이므로 위기 상황(자해 암시 등) 발생 시 대응 흐름과 전문 기관 안내 방식을 명시해야 합니다."

**(b) 답변 초안**

한벗은 매 턴 위기 신호를 두 경로로 확인합니다. 로컬 키워드 게이트가 명시적 자살·자해 표현을 잡으면 언어 모델을 거치지 않고 바로 안전 모드로 전환하고, 그 밖의 발화는 응답 첫 줄의 위험 태그(L0·L1·L2)로 판정합니다. 두 경로는 같은 음성 인식 결과에 의존하므로 이중 구조가 안전성을 높인다고 가정하지 않고, 키워드 단독·태그 단독·결합 방식을 같은 평가 세트에서 비교하며 음성 입력부터 안내 재생까지 전체 경로도 평가합니다. L1이면 미리 녹음한 안전 스크립트와 109 자살예방상담전화 카드를 보여주고 "지금 안전한 곳에 있어?"라고 묻습니다 [P82]. 고정 카드는 범용 음성비서가 위기 관련 질문에 비일관적으로 응답했다는 보고 [P74]를 참고한 설계 판단이며, 카드의 효과를 검증한 연구는 아닙니다. LLM 챗봇은 위험 수준별 질문에 직접 답하는지가 중간 위험 구간에서 일관되지 않았습니다 [P73]. 응답 정책 연구라서 탐지 성능 근거는 아니지만, 중간 위험 유형을 평가에서 따로 다룰 이유가 됩니다. 안전 모드는 대화를 끊지 않고 짧은 공감 응답과 카드를 유지합니다. 위험 신호가 쌓일수록 한 모델이 대화를 줄인 것이 임상 모범 사례와 어긋난다는 평가가 있지만 [P72], 사람에게 연결한 뒤 대화를 끝내자는 의견도 있어 [P76], 이 선택은 설계 판단으로 두고 전문가 검토를 받습니다. 한국어 근거는 제한적입니다. 한국어 자살 위험 분류 연구는 게시글 기반(이진 F1 0.88, 4단계 F1 0.72)이고 [P70], 대화 발화 단위 연구는 이번 조사에서 찾지 못했습니다. 그래서 번역 사례와 한국어로 직접 작성한 다중 턴 시나리오로 평가 세트를 만들고 시나리오 단위로 개발·평가를 나누며 [P77], 목표 수치는 테스트 세트 성능일 뿐 실제 안전 보증이 아님을 밝힙니다.

**오탐률의 운영상 의미(설명용 가정, 자체 계산)**: 재현율 0.90, 턴 단위 오탐률 10%라고 가정한다. 위기 발화 비율이 1%면 L1 경보의 정밀도는 약 8.3%, 5%면 약 32%, 0.1%면 약 0.9%다. 설계서 가정(분당 3턴 × 10분 = 세션 30턴, 7.1 a1·a3)이면 비위기 사용자에게 세션당 약 3회의 잘못된 안전 모드 진입이 생긴다. 따라서 10%를 턴 단위 목표로 쓰면 서비스가 성립하지 않는다. 턴 단위 오탐 목표와 대화 단위 목표를 따로 정해야 한다(팀 결정 필요, W1). 실제 위기 발생률 추정치는 아니다.

**(b) 답변 초안**

원칙은 두 가지입니다. 필요 없는 데이터는 만들지 않고, 목적이 끝난 데이터는 지체 없이 파기합니다. 개인정보 보호법 제21조도 불필요해진 개인정보를 지체 없이 파기하도록 하되 다른 법령의 보존 의무를 예외로 둡니다 [P87]. 원본 음성은 자체 저장소에 저장하지 않습니다. 이것은 데이터 최소화를 위한 설계 판단입니다. 참고한 음성 재식별 실험은 비교 횟수가 늘수록 잘못된 매칭이 늘어 실제 재식별은 어려워졌다고 보고했고, 저자들은 화자식별 기술이 발전하면 위험이 커질 수 있다고 논의했습니다 [P85]. 외부 음성 인식 업체의 보관 조건은 W1에 약관으로 확인하기 전까지 미확정입니다. 목소리로 개인을 알아보는 특징값(voiceprint)도 만들지 않습니다. 시행령의 생체인식정보는 특정 개인을 알아볼 목적으로 기술적 수단을 통해 생성한 특징 정보이기 때문입니다 [P100]. 음성에서 추정한 감정값이 민감정보인지는 확인하지 못해, 보수적으로 별도 동의와 분리 저장을 적용합니다. 제3자 광고·분석 도구는 넣지 않습니다. 미국·호주의 우울·금연 앱 36개 중 33개가 실제로 제3자에 데이터를 보냈고 처리방침만으로는 이를 알기 어려웠습니다 [P83]. 기억은 저장 전에 항목별 승인을 받습니다. 한 연구에서 ChatGPT 메모리 사용자 20명 대부분이 저장된 내용을 보고 부정적 기대 위반을 겪었고 [P65], 다른 연구에서는 80명의 메모리 2,050건 중 96%가 사용자의 명시적 요청 없이 시스템 주도로 생성됐습니다 [P67]. 이 수치가 동의 부재나 오류를 뜻하지는 않으므로 항목별 승인의 효과는 W6에서 따로 봅니다. 보관 기간은 데이터별 목적·필요성·종료 조건과 별도 보존 의무를 검토해 정합니다. 과거의 "1년 미이용 시 파기" 유효기간제는 2023년에 폐지됐지만 [P88], 그것이 보관 재량을 뜻하지는 않습니다. 삭제 요청 24시간 처리는 내부 처리 목표이며, 법적 적정성은 법무 검토에서 따로 봅니다.

## 4. 미확인·추가 확인 필요

본문에 사실로 쓰지 않은 항목이다. 검증표의 C·확인불가 판정이며, 노트 오류가 교정된 경우 교정된 사실은 1~3절에 썼다.

**음성 파이프라인**
- Silero를 다룬 학술 논문이 P1 "1건뿐": 이번 조사 범위의 한정 표현으로만 쓴다. 확인: 검색식을 기록한 재검색.
- Silero 고정이 Smart Turn과의 정합성상 필수: 원문은 "Silero 같은 VAD". 확인: 불필요(표현 삭제).
- Smart Turn 추론 시간이 TTFA에서 무시 가능: W2 실측 전까지 미확인.
- Smart Turn 학습 데이터가 영어·스페인어 중심: v3.1 글은 새로 추가한 인간 음성만 언급. 확인: 데이터셋 카드.
- VAP의 Interspeech 2022 게재: arXiv는 "Submitted". 확인: ISCA Archive.
- Inoue 결과가 한국어 학습 필요성을 증명: 한국어 미실험. 간접 근거로만.
- Skantze 2021 리뷰(Computer Speech & Language 67:101178): 서지만 B, 본문 미열람. 확인: DOI 본문.
- Full-Duplex-Bench가 "1초 이내 중단·재응답" 목표의 근거: 지표가 응답 지연이라 다름. 1초는 자체 목표.
- Talking Turns가 한국어 "응/음" 정책을 검증: 아님.
- CosyVoice 2 스트리밍 저하가 "작다": 기준·유의성 없음. 150ms 지연은 근거 없음.
- VoXtream 102ms가 "이론적 하한": 특정 GPU 실측치.
- 문장 경계 청킹이 운율에, 절 단위가 지연에 유리: 출처 없음.
- naive streaming MOS 3.46 vs 어댑터 4.12: 원 논문 불명.
- "1초 TTFA는 인간 대비 달성 불가": 논리적 비약(불일치).
- 벤더의 "1초 이내" 자연스러움 기준: 통제 실험 출처 없음.
- RTZR 스트리밍 지연·CER: Wiki `src-rtzr-2026-korean-stt-benchmark` 원문 URL·수치 미확인. 확인: 원문 확보.
- TEN VAD의 정밀도 우위: 자체 주장(A는 주장의 존재만). 확인: 공개 테스트셋·재현 스크립트 실행.

**SER**
- "IEMOCAP 화자 독립 상한 73%": 특정 연구(2111.02735)의 최고 WA 73.01%일 뿐 상한이 아니다.
- "0.8139보다 낮으므로 0.70은 보수적": 지표·분할이 달라 불일치.
- KEMDy19 0.5초 UA −10.61%, 3초 −5.08%: 원문 조회 실패, %와 %p 불명. 확인: AES 2024 발표 원문.
- "2초 미만이면 확인 질문 생략"을 P33이 정당화: 아님. 팀 정책.
- "슬픔이 코덱에 가장 취약": 초록은 취약 감정 열거만. 확인: EMO-Codec 감정별 표.
- α=0.25가 정확도 상한: 아님. 라벨 불확실성이 해석을 제한한다는 뜻.
- 4라벨 = basic emotion 이론 채택: 단정 불가.
- Borre 결과로 20대 연령 편향이 작다: 미검증.
- Shibata가 "오추정+단정 공감 → 반감"을 실험으로 입증: 배경 서술일 뿐(불일치).
- Bickmore CHI 2007(정식 제목 Practical Approaches to Comforting Users with Relational Agents): 결론은 검색 색인 B, 본문·표본 미확인. 확인: 저자 PDF 열람.
- EmoBot(arXiv 2411.02831): 텍스트 전용이 아니라 음성 입력도 받음. 혼합 감정 오분류 사례 대응 미확인. 근거 약해 P 번호 없음.
- 확인 질문이 단정·무반응보다 피해를 줄임: 직접 근거 없음. W6 측정.
- SER을 위기 탐지에 안 쓰므로 슬픔 미검출 위험이 낮음: 설계 사실과 위험 판단은 별개. 검증 대상.
- "최소 200발화·20화자·클래스당 50건 필요": 검정력·허용오차 미정. 확인: 목표 정밀도 정한 뒤 계산.
- KEMDy20 외부 평가자 10명: 원문 미확보. 확인: ETRI 데이터 문서.
- 한국 서비스에 EU법 미적용, 소비자 앱이면 금지 밖: 법률 검토 전 추정.
- 민감정보는 별도 동의로만 처리 가능: 법령상 다른 근거도 있음.
- 음성 유래 감정값의 민감정보 해당 여부: 확인: PIPC 질의 또는 법무 검토.
- emotion2vec+·SenseVoice 한국어 평가 논문 "없음": "이번 검색에서 미발견"으로만.

**안전·개인정보·HCI**
