## 0. 한 장 요약

1. **무엇을**: 대학생이 음성으로 고민을 말하면 들어주는 AI 친구. React 웹앱(모바일 브라우저 우선)으로 통화하고, 통화 후 요약과 기억 후보를 사용자가 승인한다.
2. **차별점(가설)**: 음성 감정 단서(억양·속도·멈춤)는 확인 질문으로만 쓴다. 기억은 "내가 말한 것"과 "한벗이 느낀 것"을 나누고, 저장 전에 동의를 받는다. 위기 시 109 안내와 안전 모드로 전환한다. 치료가 아닌 경청·동반을 내세운다 [[claim-bench-7-no-therapy-positioning]] [[claim-bench-8-emotion-cue-as-question]]. 이 차별점이 사용자 가치로 이어지는지는 W6에서 검증한다(0.1절 H3·H4).
3. **참고 앱**: 통화 화면 Gemini Live, 끼어들기 Gemini·ChatGPT·Character.AI, 기억 편집 Nomi·Replika, 기억 제안 Kindroid, 위기 화면 Wysa, 통화 후 결과 클로바 케어콜.
4. **스택**: React + Pipecat + RTZR STT + Smart Turn v3 + emotion2vec+ base + Claude 스트리밍(위험 태그 포함) + Typecast TTS + Postgres/pgvector [[topic-tech-mvp-stack]].
5. **7주 범위**: W1에 라이선스 확인과 문제 인터뷰를 한다. W5까지 P0를 끝내고 테스트 시작 게이트(8.4절)를 통과해야 W6에 사용자 20~30명 테스트를 한다. W7은 분석과 발표다. 주차별 중단 기준과 축소 범위는 8.3절에 있다.
6. **목표**: TTFA P50 ≤ 1.0s(Wiki 목표). 현재 예산 합계로는 미달할 수 있어 W2 측정 후 P50 ≤ 1.5s로 조정할지 정한다(7.2절). 위기 평가 목표는 테스트 세트 성능이지 실제 안전성 보증이 아니다.
7. **최대 미확인 사항**: 문제·지불 의사(H1·H5), emotion2vec 가중치·openSMILE 라이선스, 한국어 SER 성능, 커뮤니티 플러그인 성숙도, 109 연동, 실측 TTFA.

**논문 근거 보강(2026-10-26, 비평 반영)**: TTFA 목표, SER 합격선·점수 임계값, 위기 분류 재현율 목표에 이제 논문 근거와 한계가 붙어 있다. TTFA 1.0s는 7.2 정의로 P50·P95를 직접 재고, 사람 턴 간격(약 200ms)과 상용 앱 평균(약 1.37s)은 측정 조건이 달라 참고 맥락으로만 쓴다 [P15][P18]. SER UA 0.70과 점수 0.6은 한국어 공개 근거가 없거나 보정되지 않은 값이라 W3 측정 전까지 가설이다. 0.6은 확률로 해석하지 않고 임계값 선택용 세트와 최종 평가 세트를 분리한다 [P21][P39]. 위기 재현율 0.90은 테스트 세트 목표이며 한국어 근거는 게시글 기반뿐이다 [P70]. 기술 성능과 H1~H5의 연결은 근거 문서 0.1절에 있다. 번호 [P#]의 출처는 10.1.1절, 세부 근거는 `reports/한벗 기술 논문 근거.md`에 있다.

## 1. 벤치마크 지도: 기능별로 따라 할 앱

## 2. MVP 기능 명세

### 2.1 공통 수용 조건

| 조건 | 내용 |
|---|---|
| 기기·환경 다양성 | P0-1~3은 기기 3종(iPhone Safari, Android Chrome, 노트북 Chrome) × 환경 2종(조용한 실내, 생활 소음) × 출력 2종(이어폰, 스피커)으로 측정한다. 칸별 결과와 실패 사례를 함께 보고한다 |
| 화자 다양성 | 팀 4명 외에 6명 이상(성별, 지역 억양 다양)을 포함한다 |
| 판정 지침·평가자 일치도 | 사람이 판정하는 지표(조언 발생, 단정 표현, 확인 질문 적절성, 위기 응답 적절성)는 판정 지침서(정의 + 예시 각 5개)를 먼저 만든다. 2인이 독립 판정하고 Cohen's κ를 보고한다. κ < 0.6(임시 운영 기준)이면 지침을 고친 뒤 다시 판정한다 |
| 해석 범위 | "10회 중 9회" 같은 기준은 그 표본의 결과일 뿐 서비스 성공률을 보증하지 않는다 |

### 4.3 턴 1회 시퀀스
```
t0 = 사용자 발화 종료 VAD 시점(마지막 음성 프레임 시각)  ← TTFA 시작점
 ├ 턴 감지 대기: VAD stop 0.2s(기본값 [S37]) + Smart Turn 판정(미실측)
 ├ RTZR Finalize → final 전사
 ├ (병렬) SER·운율: 해당 턴의 Claude 호출 시작 전까지 오면 사용, 아니면 폐기
 ├ (병렬, partial 시점) 메모리 prefetch
 ├ KeywordGate(로컬) → 양성이면 Claude를 거치지 않고 안전 스크립트
 ├ Claude 첫 토큰(위험 태그 수 토큰 포함)
 ├ 위험 태그 판정 → 첫 문장 집계
 ├ TTS 첫 청크 → 네트워크 → 클라이언트 재생 버퍼
t1 = 클라이언트 첫 오디오 재생 시작  ← TTFA 끝점
```
시간 예산 합계와 목표 조정 규칙은 7.2절에 있다.

### ① 오디오 캡처·전송 (React + Pipecat 클라이언트)
- **선택**: `@pipecat-ai/client-js` + SmallWebRTC. UI는 voice-ui-kit(React + Tailwind 4, BSD-2-Clause) [S26][S27].
- **레퍼런스**: [S26] A, [S27] A, [S28] `simple-chatbot`·`push-to-talk` A.
- **단계**: 1) `simple-chatbot`을 그대로 로컬에서 구동한다. 2) 클라이언트를 Vite React로 분리하고 `ConnectButton`·`UserAudioControl`·`VoiceVisualizer`를 배치한다. 3) `PipecatClient`를 `enableMic:true`로 생성한다 [S26]. 4) 서버의 전사·봇 상태 이벤트를 자막과 오브에 연결하고, 첫 오디오 재생 시각을 서버로 보낸다. 5) 2.1절 기기 매트릭스로 테스트한다.
- **코드 골격**: 노트에 그대로 인용할 공식 코드 블록이 없다. [S26]의 `PipecatClient` + `enableMic:true` 예제와 voice-ui-kit 설치 안내의 `@pipecat-ai/client-react` [S27]를 설치 버전대로 따른다.
- **함정**: iOS 홈 화면 PWA에서 getUserMedia 버그 보고가 2020년·2024년에 있다(주로 카메라) [S29]. MVP는 Safari 브라우저 접속을 기본으로 한다.

- **근거 논문**: [P1] 영어 실환경에서 Silero가 WebRTC·RMS보다 우수(수치는 초록에 없음, A) · [P2] 잡음 혼합 0 dB, FPR 5%에서 TPR Silero 87.7% vs WebRTC 50%(벤더 자체 평가, A). 한국어·모바일 소음 수치는 없어 W2에 직접 잰다 → 자세한 내용은 reports/한벗 기술 논문 근거.md §1

### ② STT (RTZR 스트리밍)
- **선택**: RTZR `sommers_ko` [[claim-tech-3-stt-tts-vendors]]. Pipecat 커뮤니티 서비스 `pipecat-rtzr`(공식 목록에 등재) [S32].
- **레퍼런스**: [S30] A, [S31] A, [S32] A.
- **프로토콜** [S30][S31] A: `/v1/authenticate`로 토큰을 받는다 → `wss://openapi.vito.ai/v1/transcribe:streaming`에 `Authorization: Bearer`로 연결한다 → LINEAR16 오디오를 보낸다 → 응답의 `final`, `alternatives[].text`를 읽는다 → 턴 확정은 `{"type":"Finalize"}`(연결 유지) → 종료는 `EOS`. `sample_rate`는 8000~48000 범위에서 필수로 지정한다.
- **단계**: 1) `uv add pipecat-rtzr`, `RTZR_CLIENT_ID/SECRET`를 설정한다. 2) 서버에 실제로 들어오는 sample rate를 로그로 확인해 지정한다(16k라고 가정하지 않는다). 3) VAD 뒤에 배치한다. 4) Finalize 전송 시점을 패키지 코드에서 확인한다. 5) 2.1절 화자·환경 조건에서 CER을 측정한다(목표 ≤ 8%).
- **코드 골격** [S33] (노트 인용, **검증 C: 원문 미확보 → 설치 후 README와 대조**):
```python
from pipecat_rtzr import RTZRSTTService
stt = RTZRSTTService(
    client_id=os.getenv("RTZR_CLIENT_ID"),
    client_secret=os.getenv("RTZR_CLIENT_SECRET"),
)
# Add stt to your pipeline, after a VAD
```
- **함정**:
  - (a) API 기본 도메인 `CALL`은 헤드셋·근접 마이크에도 적합하다고 공식 문서에 적혀 있다 [S31]. 바꿀지는 CER 결과로 정한다.
  - (b) LiveKit 플러그인의 기본 sample_rate는 8000이다 [S34]. LiveKit으로 바꾸면 이 값도 바꾼다.
  - (c) 연결 후 60초 안에 오디오 청크를 보내지 않으면 종료될 수 있다 [S31]. 보류 중에도 무음 프레임을 보낸다.
  - (d) 플러그인의 기본값·keepalive·호환 버전은 C다. 버전을 고정하고, 막히면 공식 WebSocket을 직접 구현한다.

- **근거 논문**: [P3] Whisper large-v2 zero-shot KsponSpeech eval-clean CER 14.66%, 미세조정 10.48%(A) · [P4] KsponSpeech 약 969시간, 간투사·반복 태그(A). RTZR 독립 학술 평가는 없으므로 CER ≤ 8%는 팀 녹음 기준 목표로 둔다 → 자세한 내용은 reports/한벗 기술 논문 근거.md §1

### ③ 턴 감지·끼어들기 (Smart Turn v3, barge-in)
- **선택**: Silero VAD + Smart Turn v3.2. Smart Turn v3.2는 한국어를 포함한 23개 언어, 약 8M, 16kHz 최대 8초 입력이다 [S36] A. CPU 추론은 대부분의 클라우드 인스턴스에서 100ms 미만이라는 조건부 설명이 있다 [S36] B.
- **레퍼런스**: [S35] A, [S36] A, VADParams 기본 start/stop 0.2s [S37] A.
- **단계**: 1) 아래 스니펫으로 stop 전략을 설정한다. 2) 시작 전략이 끼어들기를 트리거하면 봇 발화와 진행 중 작업이 즉시 취소된다 [S35]. 기본 ON으로 둔다. 3) [보류] 탭은 서버 인터럽트 이벤트로 보낸다. 4) 머뭇거림이 포함된 50턴 이상으로 조기 종료율을 측정한다. 5) 위기 안내 중에 끼어들면 카드를 유지하고 `safety_reminder_pending=true`로 세션 말미에 다시 안내한다.
- **코드 골격** [S35] A:
```python
from pipecat.audio.turn.smart_turn.local_smart_turn_v3 import LocalSmartTurnAnalyzerV3
from pipecat.turns.user_stop import TurnAnalyzerUserTurnStopStrategy

stop_strategy = TurnAnalyzerUserTurnStopStrategy(
    turn_analyzer=LocalSmartTurnAnalyzerV3()
)
```
- **함정**: Smart Turn과 RTZR 서버 끝점 검출이 턴을 중복 확정할 가능성은 추론일 뿐이다(C). W2 로그로 확인한다. 한국어 고민 발화에서 Smart Turn의 정확도는 이번 조사 범위에서 공개 수치를 찾지 못했다.

- **근거 논문**: [P6] Smart Turn v3 한국어 정확도 96.85%(n=890), False Positives 1.12%, False Negatives 2.02%, CPU 12.6~94.8ms(전처리 포함, 벤더 테스트셋, A) · [P13][P14] 끼어들기 후 응답 지연 Moshi 0.257s~dGSLM 2.531s, 오디오 모델의 과도한 끼어들기·백채널 부족(영어, A) · [P11] 백채널 생성 시점 예측 연구(한국어 M-F1 35.1%, A). 사용자 "응/음" 판별과는 다른 과제라 W2에 실제 겹친 발화로 잰다
- TTFA 참고 맥락: [P15][P16] 사람 턴 간격 약 200ms, 언어별 평균 차이 ±250ms 안팎(한국어 포함, A) · [P18] ChatGPT Voice 평균 TTFA 약 1,370ms(A). 측정 조건이 달라 직접 비교하지 않고 7.2 정의로 P50·P95를 잰다 → 자세한 내용은 reports/한벗 기술 논문 근거.md §1

### ④ SER (emotion2vec+ turn-end → 확인 질문)
- **선택**: emotion2vec+ base(약 90M, 16kHz, utterance 단위, 9라벨) [S38] A. 2순위는 SenseVoice-Small [[claim-tech-1-ser-model]].
- **레퍼런스**: [S38] A, [S39] A, FrameProcessor 골격 [S41] A.
- **단계**:
  1) `pip install -U funasr modelscope`
  2) 발화 시작~종료 오디오를 버퍼링하는 FrameProcessor(`process_frame`/`push_frame`)를 만든다. 민감정보 동의가 없으면 이 프로세서를 넣지 않는다.
  3) 턴이 끝나면 16kHz 임시 WAV로 `generate`한다(배열 입력 지원은 공식 예제로 확인하지 못함).
  4) 결과에 `utterance_id`와 `created_at`을 붙인다. **해당 턴의 Claude 호출이 시작될 때까지 도착하지 않으면 폐기하고, 다음 턴에 쓰지 않는다.**
  5) 임시 WAV는 즉시 삭제한다.
  6) 약관을 확인한 뒤 평가한다(아래 매핑표).
- **코드 골격** [S38] A:
```python
from funasr import AutoModel

model = AutoModel(model="iic/emotion2vec_plus_base")

wav_file = f"{model.model_path}/example/test.wav"
res = model.generate(wav_file, output_dir="./outputs", granularity="utterance", extract_embedding=False)
print(res)
```

**④-1 라벨 범주 매핑 (설계)**. 평가된 범주만 제품에 쓴다.

| emotion2vec+ 라벨 [S38] | 4-class 벤치마크 | 제품 확인 질문 범주 | 문구 예 |
|---|---|---|---|
| angry | 분노 | 답답함 | "좀 답답하게 들렸는데, 맞아?" |
| sad | 슬픔 | 가라앉음·지침 | "목소리가 좀 가라앉은 것 같은데, 맞아?" |
| happy | 기쁨 | 밝음 | "목소리가 밝게 들렸는데, 맞아?" |
| neutral | 중립 | 질문하지 않음 | — |
| fearful, disgusted, surprised, other, unknown | 벤치마크 제외 | **질문하지 않음**(평가되지 않은 범주) | — |

- 평가 방법(설계): 9라벨 점수 중 4개만 남겨 재정규화한 뒤 argmax를 취한다. 화자 독립 분할에서 UA·WA와 클래스별 재현율·혼동 행렬을 보고한다. 합격선은 UA ≥ 0.70, 목표는 0.80이다 [[claim-tech-1-ser-model]]. 제품 문구("가라앉음" 등)가 적절한지는 2.1절 판정 지침으로 사람이 판정한다.
- 다른 데이터셋의 정확도는 한국 대학생의 실제 고민 발화 성능을 보증하지 않는다. 이번 조사에서 확인한 한국어 4-class 공개 수치는 AI Hub 데이터의 HuBERT 0.8139 1건이고, 화자 독립 분할 여부는 확인되지 않았다 [S15].

**④-2 확인 질문 규칙.** 수치는 모두 **임시 운영 기준**(근거 없음, W6에서 조정)이다.

| 규칙 | 내용 |
|---|---|
| 입력 형식 | `[음성 단서 utt=123] 범주=가라앉음, 말 속도=평소보다 느림, 멈춤=길어짐` (점수는 Claude에 넘기지 않는다) |
| 발화 조건 | 점수 ≥ 0.6 **그리고** 직전 5턴에 확인 질문 없음 **그리고** 민감정보 동의 ON **그리고** 안전 모드 아님 |
| 판단 보류 | 발화 < 2초, STT 결과가 빈 문자열이거나 1어절, 세션 초반(발화 3턴 또는 누적 30초 미만)에는 상대 지표(속도·멈춤)를 쓰지 않는다 |
| 점수 해석 | 모델 점수를 "맞을 확률"로 보지 않는다(보정 근거 없음). 순위용 값으로만 쓴다 |
| 문장 틀 | 한 문장으로, 응답 끝에. 단정("너 ~하구나"), 라벨 직역, 점수 언급, 진단 용어는 금지 |
| 응답 처리 | "맞아" → `confirmed`(저장은 아직 아님) / "아니야" → 해당 단서 폐기, 그 세션에서 같은 범주는 질문하지 않는다 / 무응답 → 폐기 |

**④-3 확인 질문 지표 (수용성 지표, 정확도 아님).** 사용자의 "맞아"에는 동조, 모호한 표현의 수용, 대화를 이어가려는 응답이 섞일 수 있다.

| 지표 | 정의 |
|---|---|
| 질문 발생률 | 확인 질문 수 ÷ 민감정보 동의 사용자의 전체 턴 |
| 확인 수용률 | "맞아" ÷ 확인 질문 수 (Wiki의 "확인 일치율 70%"를 이렇게 재정의한다. 목표 70%는 수용성 목표다) |
| 거절률 | "아니야" ÷ 확인 질문 수 |
| 무응답률 | 응답 없음 ÷ 확인 질문 수 |
| 침해감 | 세션 후 문항 "목소리로 감정을 짐작한 게 불편했다"(5점) |
| SER 적시 도착률 | 해당 턴 Claude 호출 전 도착 ÷ SER 실행 턴 (폐기율의 역) |

- **함정**: 가중치 `model-license`는 상업 조항을 명시하지 않았고, 출처·저자·모델명 보존 의무가 있다 [S40] A. 상업 이용 가능 여부는 확정되지 않았다. 이번 조사에서 공식 지연 수치를 찾지 못했으므로 W3에 실측한다.

### ⑧ 메모리 (4상태, pgvector → Mem0, 저장 전 승인, TTL)
- **선택**: MVP는 Postgres + pgvector 단순 RAG(k=2, 256토큰) + `block` 메타데이터로 만든다. P1에서 Mem0 OSS(Apache-2.0)로 승급한다 [[claim-tech-2-memory-architecture]] [S50][S51].
- **레퍼런스**: [S50] A, [S51] A, 블록 개념은 Letta [S52] A.

**⑧-1 기억 상태 (설계)**

| 상태 | 뜻 | 만들어지는 시점 | 블록 | UI 라벨 |
|---|---|---|---|---|
| `stated` | 사용자가 직접 말한 내용(객관적 사실로 검증된 것이 아님) | 통화 후 요약 작업이 추출 | user_stated_facts | "내가 말한 것" |
| `inferred` | 모델의 추정(SER + 텍스트) | 턴 중 단서 생성 | ai_inferred_affect | 표시하지 않음(후보에도 안 올림) |
| `confirmed` | `inferred`를 사용자가 "맞아"로 확인함 | 확인 질문 응답 | ai_inferred_affect | "한벗이 느낀 것 · 내가 맞다고 함" |
| `approved` | 사용자가 저장에 동의함(`stated` 또는 `confirmed`에서만 전이) | 통화 후 카드에서 [저장] | 해당 블록 | 위 라벨 + 저장됨 |

전이 규칙: `stated → approved`, `inferred → confirmed → approved`. **`inferred`는 `approved`로 바로 갈 수 없다.** 검색·프롬프트에는 `approved`만 쓴다. `confirmed`는 감정이 맞다는 확인이고, `approved`는 장기 저장 동의다. 둘은 다른 행위다.

- **테이블(설계)**: `memories(id, user_pk(가명), block, state, text, evidence_utterance_id, evidence_at, expires_at, embedding)`, `memory_tombstones(user_pk, text_hash, deleted_at)`.
- **단계**:
  1) 통화 후 작업이 `stated` 후보와 `confirmed` 후보만 만든다.
  2) 승인되면 임베딩을 만들고 `approved`로 바꾼다.
  3) 통화를 시작할 때 `approved` 기억을 prefetch하고, STT partial마다 보조 검색한다. 동기 호출은 하지 않는다.
  4) 하루 1회 작업이 `expires_at`이 지난 기억을 삭제한다.
  5) 수정은 행을 교체하고 다시 임베딩한다.
  6) 기억 후보 추출은 세션 종료 시 1회만 한다. 과거 전사를 다시 처리하지 않는다. 삭제된 기억과 정규화 해시가 같은 후보는 다시 제안하지 않는다.
  7) 모든 쿼리는 인증 세션의 `user_pk`로만 필터링한다(클라이언트 입력값을 쓰지 않음). Postgres 행 수준 보안(RLS)을 적용한다.
  8) 50문항 세트로 정답률을 측정한다(목표 ≥ 70%).
- **코드 골격** [S51] A(P1 승급 시):
```python
relevant_memories = memory.search(query=message, filters={"user_id": user_id}, top_k=3)
memory.add(messages, user_id=user_id)
```
  pgvector는 `config["vector_store"]={"provider":"pgvector","config":{...}}` → `Memory.from_config`로 설정한다 [S50] A. `metadata={"block": ...}` 태그 저장은 예제 방식으로 보아 가능하다 [S50] B.
- **함정**:
  - Mem0 검색 p95는 1.44s다(벤더 자체 연구, LoCoMo 조건) [S18]. 턴 안에서 동기 호출하면 안 된다.
  - `embedding_model_dims`의 기본값은 1536이지만, 쓰는 임베딩 모델의 차원과 반드시 맞춘다 [S50] A.
  - Mem0 `add`는 자동으로 추출해 저장하므로 **승인된 텍스트만** 넘긴다(설계).
  - Letta 블록은 값 전체를 교체하는 방식이라 동시에 수정하면 마지막 쓰기가 덮어쓴다 [S52] A.

- **근거 논문**: [P60] LoCoMo J RAG(k=2) 60.97%, Mem0 66.88%, p95 1.44s(벤더 자체, A) · [P65] 연구 참가자 20명 대부분이 저장된 기억 확인 후 부정적 기대 위반(A) · [P67] 80명의 ChatGPT 메모리 2,050건 중 96% 시스템 주도 생성(동의 부재 증명 아님, A) · [P61][P68] 지식 갱신·기권 평가 축, 통제 지시 세 유형 모두 지키는 시스템 없음(B) → 자세한 내용은 reports/한벗 기술 논문 근거.md §1

| 단계 | 구성 | 시점 | 출력 |
|---|---|---|---|
| ① KeywordGate | 로컬 키워드·패턴 사전(자살·자해 의도·계획·수단) | STT final 직후, Claude 호출 전 | 양성 → Claude를 호출하지 않고 즉시 안전 모드 |
| ② 위험 태그 | **Claude 응답 호출에 분류 지시를 포함**한다. 응답 첫 줄에 `<risk>L0|L1|L2</risk>`를 출력한다(추가 호출 없음, [[topic-tech-mvp-stack]]와 일치) | 생성 스트림 첫 토큰들 | 서버가 파싱해 태그를 제거한다. TTS는 태그 판정 후에만 시작한다 |
| ③ L1 처리 | 태그가 L1이면 생성문을 폐기하고 고정 안전 스크립트(사전 합성 오디오)를 재생한다 | 태그 수신 즉시 | 안전 모드 |
| ④ L2 누적 | 세션 점수: 텍스트 L2 태그 1점 + 같은 턴의 음성 저각성 단서 0.5점(민감정보 동의 시). **음성 단서만으로는 점수가 오르지 않는다** | 매 턴 | 2점 이상이면 부드러운 안내 1회. 이후 2점마다 재안내, 최대 2회 |
| 실패 처리 | 태그가 없거나 파싱할 수 없으면 L0으로 보되 KeywordGate 결과는 유지한다. 파싱 실패를 기록한다. LLM·TTS 장애 시 안전 스크립트는 사전 합성 오디오와 화면 카드로 제공한다 | — | — |
| 대안 | **별도 분류 호출**(응답 생성과 병렬): W3 개발 세트에서 태그 형식 준수율이 99% 미만이거나 L1 재현율이 미달하면 전환한다. 비용과 지연 증가는 W3에 측정한다 | — | — |

L2의 점수·임계·재안내 횟수는 모두 임시 운영 기준이다. L2는 **텍스트 단독 경로**와 **텍스트 + 음성 경로**를 따로 평가한다. 음성 단서가 탐지 성능을 개선하지 않으면 L2에서 음성 가산을 뺀다.

**⑨-2 위기 운영 (설계)**

| 항목 | 운영 기준 |
|---|---|
| 담당자와 역할 | 위기 운영 책임 = PM·안전, 부책임 = AI. 역할은 로그 점검, 오탐 분석, 문구·규칙 수정 요청, 자문 연락이다. **팀은 실시간 상담·개입을 하지 않는다** |
| 대응 가능 시간 | 앱의 자동 안내는 24시간 동작한다. 팀 로그 점검은 W6 기간 매일 1회(예: 22시)이며 실시간이 아니다. 온보딩과 설정에 "한벗 팀은 실시간으로 연락하지 않아요. 지금 위급하면 109로"를 고지한다 |
| 점검 범위의 한계 | 민감정보 동의가 없는 사용자는 위기 로그를 저장하지 않으므로(발생 집계도 하지 않음) 팀 점검 대상에서 빠진다. 이 한계를 W6 결과 보고에 적는다 |
| 테스트 참가자 사전 절차 | 참가 설명서에 위기 안내 절차, 팀 연락 범위, 외부 기관 정보를 적는다. 참가자에게 개별 연락할지는 연구윤리 절차와 자문 결과로 정한다(**미확정**) |
| `tel:109` 실패 시 | 링크 실패는 앱이 감지할 수 없다. 그래서 카드에 번호를 항상 큰 글씨로 함께 적고 [번호 복사] 버튼을 둔다(노트북·태블릿 대비). 지역 정신건강복지센터 안내를 병기한다. 긴급 신고 번호를 병기할지는 자문 후 확정한다. 109 공식 API·연계 가이드라인은 확인하지 못했다(C) |
| 안전 모드 진입 | L1(KeywordGate 또는 태그). 공감 1문장 → 109 안내 → "지금 안전한 곳에 있어?" → 109 카드 전면 표시, 모드 전환 잠금 |
| 안전 모드 해제 | 사용자가 "안전해"라고 답하고, 이후 연속 3턴(임시 운영 기준) L1이 없으면 일반 모드로 돌아간다. 109 카드는 하단에 고정하고, 세션 말미에 다시 안내한다. 응답이 없거나 위험 신호가 이어지면 안전 모드를 유지하고, 통화 종료 시 카드 화면으로 이동한다 |
| 오탐 정정 | 안전 모드에서 [그런 뜻 아니었어] 버튼 또는 같은 뜻의 발화 → 사과 1문장 → 일반 모드 복귀(카드 하단 유지). 오탐 표시는 민감정보 동의 시에만 기록한다. 주간 오탐 분석 결과는 **개발 세트에만** 반영한다 |
| 휴식 알림과의 관계 | 안전 모드 중에는 휴식 알림과 사용 시간 제한을 보류한다 |

| 지표 | 유형별 재현율, 오탐률(비위기 대조 중 L1 판정 비율), 95% 신뢰구간, 태그 형식 준수율, 응답 적절성(2인 판정 + κ) |

| 공개 프로토콜 | RAND 5등급 질문셋 방식, 전문가 패널 평정은 [[claim-bench-3-safety-protocol]]을 따른다(출시 전 항목) |

### ⑩ 동의·개인정보 (3단 동의, 원본 음성 폐기, 삭제)

**⑩-3 통화 중 철회 (설계)**: 설정에서 S를 끄면 서버에 `consent_revoked` 이벤트가 간다. 서버는 다음 순서로 처리한다. ① SER·Prosody 프로세서 비활성 플래그 ② 진행 중인 SER 작업 취소 ③ 오디오 버퍼 폐기 ④ 이미 만들어진 `inferred`·`confirmed` 후보 폐기 ⑤ 저장 직전에 동의를 다시 확인한다(write-time check). 같은 세션은 R 전용 기능으로 계속된다. 기존에 저장된 S 데이터는 삭제 큐로 보낸다.

- **단계**:
  1) `consents(user_pk, type, granted_at, revoked_at, version)` 테이블을 만든다.
  2) 세션 시작과 철회 이벤트에서 프로세서를 넣거나 뺀다.
  3) 삭제 요청은 큐로 처리한다.
  4) 삭제 24h, 철회, 격리 테스트를 CI에 둔다.
  5) 벤더별 학습 사용 금지·국외이전·보존 기간 조항 표를 만든다(W1).
- **함정**: "음성으로 추정한 감정 = 건강정보"라는 PIPC 공식 해석은 없다(C). 보수적 가정을 유지한다. 메모리 UI만으로 적법성이 모두 충족되지는 않으므로 법무 검토를 1회 받는다.

### ⑪ 사용 시간 제한·휴식 알림
- **선택**: 연속 60분 휴식 알림, 일일 60분 이상 또는 주 6일 이상이면 오프라인 관계를 권유한다 [[claim-tech-8-crisis-referral-flow]]. 이 수치는 **임시 운영 기준**(근거 없음, W6에서 조정)이다. 사용 빈도만으로 문제 있는 이용을 판별할 수는 없다. 무료 일일 분 상한은 7.3절 계산과 H5 결과로 정한다.
- **단계**:
  1) 서버가 세션과 일일 사용 분을 집계한다.
  2) 경계에 도달하면 다음 AI 턴 끝에 고정 문구("한 시간쯤 이야기했네. 잠깐 쉬었다 할까? 계속해도 괜찮아.")를 넣는다.
  3) 화면에 [쉬기]/[계속하기] 토스트를 띄운다(ChatGPT "Keep chatting"의 변형 [S10]).
  4) 안전 모드 중에는 알림을 보류한다.
  5) 평가한다: 알림 후 행동(종료/계속)과 설문 3문항(알림이 불편했다, 일상에 방해가 됐다, 알림이 적절했다)을 함께 본다.
- **함정**: 알림 후 종료율은 행동 지표일 뿐 의존 감소의 근거가 아니다. 강제 종료는 위기 사용자를 끊을 수 있으므로 MVP는 알림만 한다(설계).

- **근거 논문**: [P90] 4주 RCT 981명, 자발적 고사용과 외로움·의존 증가가 관련(인과 아님, A) · [P93][P94] 의존 측정 척도 후보(α > 0.7 A / B). 60분·주 6일 기준을 뒷받침하는 논문은 없다 → 자세한 내용은 reports/한벗 기술 논문 근거.md §1

### ⑫ 통화 후 요약
- **선택**: 통화가 끝나면 Claude를 비동기로 1회 호출한다. "정리" 모드 규칙을 따른다.
- **출력 스키마(설계)**: `{summary[≤3], confirmed_affect[](확인된 감정만), next_step(사용자가 말한 계획이 있을 때만, 없으면 null), memory_candidates[{state: stated|confirmed, block, text, evidence_utterance_id}]}`
- **단계**: 1) 전사와 확인 응답을 입력한다. 2) JSON 검증에 실패하면 1회 재시도한다. 3) 후보를 표시한다. 4) `inferred`(미확인)·"아니야"로 답한 감정·삭제 tombstone과 같은 후보는 제외한다. 5) 표시 지연이 ≤ 15s(목표)인지 측정한다.
- **함정**: 진단성 표현("우울 증상")은 금지 목록으로 검사한다. 위기 세션의 요약 화면에는 109 카드를 함께 보여준다. "다음 행동"은 사용자의 발화에 근거가 있을 때만 쓴다. "들어줘" 모드 세션에서 새 조언을 만들어 내지 않는다.

- **근거 논문**: 요약 자체를 평가한 논문은 없다. 간접 근거만 있다: [P64] 축어 인용은 프라이버시 우려 유발(A) · [P65] 저장 내용을 처음 볼 때의 놀람(A) → 요약은 재진술로 쓴다 → 자세한 내용은 reports/한벗 기술 논문 근거.md §1

### 7.3 단위경제성 (H5, 추정)

가정: STT+TTS 원가는 분당 45.5원(STT 16.7원 + Typecast 초과 단가 28.8원)이다. 누진 할인과 Claude·서버·결제 수수료는 반영하지 않았다. 가격은 ₩9,900(가설 하단)으로 둔다.

| 이용자 유형(월 사용) | STT+TTS 원가 | ₩9,900 대비 | 비고 |
|---|---|---|---|
| 라이트 30분 | 1,365원 + 30L | 여유 있음 | — |
| 중간 120분(주 3회 × 10분) | 5,460원 + 120L | Claude 단가에 따라 빠듯함 | — |
| 헤비 600분(일 20분) | 27,300원 + 600L | **적자** | 유료 플랜에도 월 분 상한이 필요하다 |
| 손익분기 사용량(유료) | 9,900 ÷ 45.5 ≈ **217분/월** | Claude 제외 상한 | Claude를 넣으면 더 낮아진다 |

무료 이용자의 월 무료 분 상한 F는 전환율 c일 때 `9,900 × c ≥ 45.5 × F × (1 − c)` 조건을 만족해야 한다(유료 이용자 원가와 Claude 제외).

| 전환율 c | 무료 상한 F |
|---|---|
| 5% | ≤ 약 11분/월 |
| 10% | ≤ 약 24분/월 |

전환율 5–10%는 근거 없는 설계 가정이다(C) [[claim-bench-6-pricing-arpmau]]. 참고로 제타의 역산 ARPMAU는 약 1,388원/월이다(회사 발언 기반 역산, B) [S22]. 따라서 "음성 무료 상한"은 수십 분이 아니라 수 분~수십 분 단위가 될 가능성이 크다. H5 측정(0.1절)과 W1의 Claude 단가 확인 후 다시 계산한다.

### 8.2 핵심 경로와 의존성
```
W1 키·약관·단가 ─▶ W2 통화 루프(P0-1~3) ─▶ W3 KeywordGate·위험 태그(P0-6) ─▶ W5 안전 모드·동의·운영 ─▶ [게이트] ─▶ W6
                         │                         └▶ W3 SER·확인 질문(P0-4, 라이선스 의존)
                         └▶ W4 요약·기억·삭제·격리(P0-8~10) ───────────────────────┘
자문 섭외(W3) ─▶ 문구 검수(W5) ─▶ [게이트]      연구윤리 확인(W1) ─▶ (필요 시) 신청(W2) ─▶ [게이트]
```
핵심 경로는 통화 루프 → 위기 분류·안전 모드 → 동의·삭제 → 게이트다. SER·확인 질문과 기억은 축소할 수 있는 범위다.

### 8.3 주차별 중단 기준과 축소 범위
| 시점 | 조건 | 조치 |
|---|---|---|
| W1 말 | emotion2vec 가중치·데이터 약관이 부정적이거나 회신이 없음 | SER은 교육 목적 비교 실험에만 쓴다. 부정적이면 SER을 P2로 강등하고, 확인 질문은 속도·멈춤 단서만으로 하거나 끈다 |
| W2 말 | H1 인터뷰에서 반증 신호(0.1.1) | 타깃 상황을 다시 정의한다. W3 이후 범위를 통화 루프 + 안전 + 요약으로 축소한다 |
| W2 말 | 10분 통화 루프 미완성 | RTZR WebSocket을 직접 구현하거나 대체 STT로 바꾼다. W3 SER 작업을 멈추고 인원을 루프에 집중한다 |
| W3 말 | 통화 루프 미완성 | **SER을 P2로 강등**하고, 기억은 "내가 말한 것"만 남긴다 |
| W3 말 | SER UA < 0.70 또는 적시 도착률 < 50% | SER을 P2로 강등한다. H3 비교는 "속도·멈춤 단서 확인 질문 ON/OFF"로 바꾸거나 취소한다 |

| W4 말 | 기억 승인·삭제 미완성 | 기억 저장을 끄고 "통화 후 요약만" 제공한다(삭제 부담을 줄임) |

| W2 이후 매주 | TTFA P50이 조정 목표 초과 | 7.2절 조정 순서를 따른다. W4까지 미달이면 발표에서 미달을 보고한다 |

### 8.4 사용자 테스트 시작 게이트 (일정과 별도로 관리)
외부 참가자 테스트는 아래 5개를 **모두** 충족해야 시작한다.

1. 위기 평가 세트 기준 통과(P0-6). 테스트 세트 성능이며 안전 보증이 아님을 참가 설명서에 적는다.
2. 전문가 문구 검수 완료(안전 스크립트, 109 카드, 요약 금지 목록).
3. 동의 8조합, 통화 중 철회, 삭제(설계 저장소), 사용자 격리 테스트 통과.
4. 연구윤리 절차(필요한 경우) 완료.
5. 위기 운영 표(5⑨-2)와 참가 설명서 확정.
