# 이미지 화면 연결 작업 카드

목표: 기존 작업 중인 친구·입장·로그인·통화 화면을 보존하면서 생성된 이미지 전체를 실제 화면 흐름에 연결한다. 사용자 요청: 추가 친구·장면·립싱크의 화면 코드 적용.

## 디자인

- 기존 팔레트 유지: 벽지 `#f7f4ef`, 소파 초록 `#4e5b3f`, 본문 `#1f1b17`, 흰색 `#ffffff`, 밤 `#241812`, 도움·종료 `#c93a2b`.
- 프리텐다드는 조작과 설명, 하이멜로디는 친구의 말에만 쓴다. 새 글꼴과 카드 격자는 추가하지 않는다.
- 홈: 친구 선택 한 줄 → 고른 친구의 방 사진과 통화 지점 → 대화 모드와 통화 버튼. 기존 하단 탭을 유지한다.
- 입장: 사진 전체 화면, 문장은 하단 여백, 세 장면은 각 3초, 마지막 거실은 사용자가 진행. 로그인 배경도 같은 빈 거실.
- 통화: 사진은 고정하고 입 프레임만 교체한다. 움직임 줄이기 설정에서는 입을 다문 정지 사진으로 표시한다.
- 노션에서 `디자인 컨셉 v3`, `디자인`, `한벗`을 검색했지만 해당 문서를 찾지 못했다. 승인된 이미지 프롬프트, 현재 토큰, Wiki의 집 컨셉으로 기존 디자인을 유지한다.

## 변경 범위와 수용 기준

1. 네 친구 선택과 저장, 친구별 방, 선택한 친구의 통화 초상 및 입 프레임.
2. 입장 네 사진 명시적 import, 장면·문구 일치, 3초 전환, 건너뛰기 및 마지막 진행 시 타이머 정리.
3. 150ms 입 프레임 전환, 발화 중단·종료·출력 음소거·친구 변경·unmount에서 정리. 출력 음량 공급 시 프레임 선택 경로를 마련한다.
4. 모의 음성의 발화 종료를 화면 상태에 알려 조용한 구간에는 입을 닫는다. 실제 음성 서비스 구현은 이 작업에 포함하지 않는다.
5. AI 고지·SOS·3단 동의·기억 승인·삭제 동작을 유지한다. 계약이나 API는 변경하지 않는다.
6. 기존 staged/unstaged 변경을 덮어쓰거나 되돌리지 않는다. 커밋·푸시는 하지 않는다.

검증: 관련 동작 테스트, 전체 웹 테스트·린트·타입·빌드, `scripts/lint-all.sh`, 모바일·작은 화면·통화의 브라우저 캡처, 독립 코드 리뷰 기록. 상위 심각도 문제가 남으면 해결 후 완료한다.

## 적용 및 검증 기록 (2026-11-14)

- 친구 네 명을 홈과 내 방에서 선택한다. 선택값은 기기에 저장하며 방과 통화 이미지가 함께 바뀐다. 카드에서도 각 친구의 `mouth-closed`를 공유해 통화 대기 화면과 구도가 같다.
- 입장 사진 네 장과 마지막 진행 버튼, 일시 정지, 건너뛰기, 내 방의 다시 보기를 연결했다. 로그인 배경은 `intro/home.jpg`다.
- 통화 프레임은 150ms 간격이다. 발화 종료, 끼어들기, 통화 종료, 스피커 음소거, 보류에서는 닫힌 입으로 돌아간다. 타이머는 친구 변경과 화면 이탈 때 정리한다.
- 실제 음성은 아직 모의 클라이언트다. `getOutputLevel()`에 출력 음량이 공급될 때의 프레임 선택은 테스트했고, 실제 `AnalyserNode` 연결은 이번 작업에 포함하지 않았다.

브라우저 결과: [동작 확인](screenshots/image-integration/browser-check.json), [작은 화면·데스크톱 확인](screenshots/image-integration/layout-check.json).

현재 연결된 새 이미지 19장 모두 2MB 이하이며 최대 285,747바이트다. [현재 파일 크기와 해시](runtime-image-validation.json)를 기록했다. 생성 당시 기록과 다른 하늘·도윤의 기존 기본 JPG는 유지하고, 앱에서는 새 닫힌 입 초상을 참조한다.

화면 캡처: [입장 거실](screenshots/image-integration/intro-home.png), [서윤의 방](screenshots/image-integration/room-seoyun.png), [말하는 통화](screenshots/image-integration/call-speaking.png), [320px 통화](screenshots/image-integration/call-320.png), [데스크톱 홈](screenshots/image-integration/room-1280.png).

처음의 타이머 검사 실패는 jsdom의 0ms `storage` 알림을 앱 타이머로 세었기 때문이다. 해당 알림을 처리한 뒤 남은 타이머를 확인하도록 테스트를 수정했다. 앱의 장면 전환 타이머 누수는 재현되지 않았다.

## 독립 리뷰

저장소 `review_code.sh`를 실행했다. Codex는 명령 실행 금지 조건 아래 로컬 파일을 읽을 수 없어 검토하지 못했고, 같은 코드를 표준 입력으로 제공하는 읽기 전용 리뷰로 보완했다. Gemini는 계정 할당량 초과(429)로 리뷰를 시작하지 못했다. 실패 로그는 `.omc/orchestra/reviews/20261114_003456_2055326_codereview_image-runtime-wiring_gemini.md.err`에 있다. 두 모델 모두 검토했다고 주장하지 않는다.

[Codex 보완 리뷰](../../.omc/orchestra/reviews/20261114_image-runtime-wiring_codex-inline.md)의 지적 두 건을 모두 반영했다.

| 지적 | 판단 및 처리 | 검증 |
|---|---|---|
| 중: 느린 이미지 로딩에서 프레임 전환 시 초상 깜빡임 | 반영. 세 이미지가 로드될 때까지 닫힌 입을 유지하고, 전부 준비된 뒤 전환 시작 | 프레임 로딩·친구 변경 테스트 추가. 브라우저에서 open 이미지 응답을 보류해 닫힌 입 유지, 응답 재개 뒤 애니메이션 시작 확인 |
| 하: 일시 정지 후 진행 막대와 장면 타이머 불일치 | 반영. 장면의 남은 시간을 저장하여 재개 | 2초 진행 → 9초 정지 → 재개 후 남은 1초에 다음 장면으로 전환하는 테스트 추가. 실제 브라우저에서도 재개 933ms 뒤 전환 확인([기록](screenshots/image-integration/intro-resume-check.json)) |

리뷰는 정적 검토였으며 실행 검증은 이 작업에서 별도로 수행했다. 커밋과 푸시는 하지 않았다.
