# 한벗 코딩 규약

짧게, 지키기 쉽게. 규약은 리뷰에서 지적할 수 있을 만큼 구체적이어야 한다. 예외는 코드 주석에 이유를 쓴다.

## 1. 함수

- **두 번 쓰면 함수다.** 같은 로직이 두 곳에 나타나면 함수로 뽑는다. 복사해서 조금 바꾼 코드는 리뷰에서 반려한다.
- **함수는 한 가지 일만.** 이름이 "그리고"로 설명되면 둘로 나눈다. `fetch_and_summarize()` → `fetch_turns()`, `summarize(turns)`.
- **순수 함수를 먼저 쓴다.** 입력만으로 출력이 정해지는 함수는 `domain/`에 둔다. I/O(네트워크·DB·파일·시각)는 `services/`·`workers/`·`api/`에서만 한다. 시각이 필요하면 `now`를 인자로 받는다.
- **이름은 동사로.** `should_ask`, `map_label`, `build_pipeline`. 불리언을 돌려주면 `is_`, `has_`, `should_`.
- **인자 4개가 넘으면 구조로 묶는다.** Python은 `dataclass(frozen=True)`, TS는 객체 하나.
- **타입을 쓴다.** Python 함수는 모든 인자와 반환에 타입 힌트. TS는 `any` 금지, `unknown` 뒤에 좁히기.
- **길이.** 함수 40줄, 파일 400줄을 넘으면 나눌 이유를 찾는다.

## 2. 인덱스와 튜플 (명시 규칙)

튜플과 인덱스는 "자리에 의미가 있다"는 뜻이다. 그 의미를 코드에 쓰지 않으면 읽는 사람이 외워야 한다. 그래서 다음을 지킨다.

### Python

| 상황 | 하는 것 | 하지 않는 것 |
|---|---|---|
| 자리마다 뜻이 다른 **고정 길이 2개** 묶음 | `tuple[int, int]` + 언패킹 `start_ms, end_ms = span` | `span[0]`, `span[1]` |
| 3개 이상이거나 필드에 이름이 필요 | `NamedTuple` 또는 `dataclass(frozen=True)` | 길이 3 이상 bare tuple |
| 같은 종류 여러 개 | `list[...]` (가변) / `tuple[X, ...]` (불변 시퀀스) | 혼용 |
| 함수가 두 값을 돌려줌 | 반환 타입을 `tuple[State, Action]`로 쓰고 호출 쪽은 언패킹 | 길이 3 이상 반환 → NamedTuple |
| 순회에 위치가 필요 | `for turn_idx, turn in enumerate(turns):` | `for i in range(len(turns)):` |
| 뒤에서 n번째 | `turns[-1]`, `turns[-n:]` (슬라이스에 주석) | 길이 계산 후 빼기 |
| 인덱스 변수 | 뜻이 보이는 이름 `turn_idx`, `speaker_idx`, 0-기반인지 주석 | `i`, `j`, `k` (한 줄 컴프리헨션 제외) |
| 딕셔너리 key로 쓰는 튜플 | 타입 별칭으로 뜻을 적음 `Span = tuple[int, int]  # (start_ms, end_ms)` | 설명 없는 튜플 key |
| 사전 접근 | `.get(key)`, 없을 때 동작을 정함 | `d[key]`로 KeyError 방치 |
| 범위 밖 인덱스 가능 | 길이 확인 또는 `next(iter(...), default)` | 그냥 `[0]` |

예.

```python
Span = tuple[int, int]  # (start_ms, end_ms), 둘 다 발화 시작 기준 상대 시각

class Cue(NamedTuple):
    label: str        # emotion2vec+ 9라벨 원문
    score: float      # softmax 확률. 보정 전에는 "순위용 값"으로만 해석
    utterance_id: int

def context_window(turns: list[Turn], n: int) -> list[Turn]:
    """직전 n턴. n=0이면 빈 리스트. turns는 오래된 것부터 정렬돼 있어야 한다."""
    if n <= 0:
        return []
    return turns[-n:]  # 뒤에서 n개 = 가장 최근 n턴

def step(state: CrisisState, signals: Signals) -> tuple[CrisisState, Action]:
    ...

new_state, action = step(state, signals)   # 호출 쪽은 반드시 언패킹
```

### TypeScript

| 상황 | 하는 것 | 하지 않는 것 |
|---|---|---|
| 고정 길이 묶음 | **라벨드 튜플** `type Span = readonly [startMs: number, endMs: number]` | `number[]` |
| 필드가 셋 이상 | 객체 타입/interface | 긴 튜플 |
| 배열 마지막·n번째 | `arr.at(-1)`, 결과 `undefined` 처리 | `arr[arr.length - 1]` 뒤 non-null 단언 |
| 순회에 위치가 필요 | `arr.forEach((turn, turnIdx) => …)` 또는 `entries()` | `for (let i…)` 와 수동 인덱싱 |
| React key | 안정된 id | 배열 인덱스 (순서가 바뀌는 목록) |
| 상태 묶음 반환 | 객체 `{ state, action }` | 튜플 (React 훅의 `[value, setValue]` 관례는 예외) |

## 3. 데이터 구분

- `data/raw`는 받은 그대로. 수정·이름 변경 금지. 폴더마다 `SOURCE.md`(출처 URL, 받은 날, 라이선스, 민감정보 여부).
- `data/interim`·`processed`는 스크립트로 다시 만들 수 있어야 한다. 손으로 고친 파일 금지.
- 모든 processed 데이터셋은 `manifest.jsonl` 한 줄 = 샘플 하나. 스키마는 `data/schemas/manifest.schema.json`. 필수 필드: `id, audio_path|text, speaker_id, split, label, label_scheme, source, license`.
- 분할은 **화자 기준**. `split`은 `train/dev/calib/test`. 같은 speaker_id가 두 split에 있으면 로더가 에러를 낸다.
- 평가 세트(`data/eval/vN/`)는 동결. 바꾸면 버전을 올리고 `CHANGELOG.md`에 이유를 쓴다.
- 민감정보(음성 원본, 감정 라벨이 붙은 발화, 위기 시나리오, 우울·불안 점수)는 `data/raw/sensitive/` 아래에만. git 제외. 접근은 팀 내 승인자만.
- 사용자 서비스 데이터는 `data/`에 절대 복사하지 않는다. 분석이 필요하면 익명 집계만.

## 4. 파이썬

- `uv`로 의존성 관리. `pyproject.toml` 하나, `uv.lock` 커밋.
- 포매터·린터 `ruff`, 타입 `mypy --strict`(domain은 필수, pipeline은 점진).
- 비동기 함수는 `async def`로 끝까지. 동기 I/O를 async 안에서 부르지 않는다(`run_in_executor`).
- 설정은 `config.Settings`에서만 읽는다. `os.environ` 직접 접근 금지.
- 비밀값은 `.env`(git 제외)와 `.env.example`(키만).
- 로그는 구조화(`structlog` 또는 `logging` + JSON). 사용자 발화 원문을 로그에 남기지 않는다. 길이·시각·라벨만.

## 5. 타입스크립트·React

- `strict: true`. `eslint` + `prettier`. import 순서는 플러그인으로 자동.
- 컴포넌트는 함수형, 파일 하나에 컴포넌트 하나. 훅은 `use` 접두사.
- 서버 데이터는 TanStack Query 훅 하나로 감싼다(`useMemories()`). 컴포넌트에서 `fetch` 직접 호출 금지.
- 사용자에게 보이는 문구는 `features/<name>/strings.ts`에 모은다. AI 고지 문구(P0-12)는 `shared/strings/disclosure.ts` 한 곳에서만 가져온다.
- 접근성: 버튼은 `<button>`, 아이콘만 있으면 `aria-label`.

## 6. 테스트

- domain 함수는 표의 모든 행을 테스트한다(8조합 동의 → 8케이스).
- 프로세서는 가짜 프레임으로 입력→출력만 본다. 벤더 API는 어댑터를 가짜로 바꾼다.
- 통합 테스트 필수 3개: RLS 격리(P0-9), 삭제 큐 24h(P0-10), 미승인 기억 비노출(P0-8).
- 수치 목표(TTFA, UA 등)는 테스트가 아니라 `ml/`의 평가 스크립트가 보고한다. 테스트는 "정의대로 계산되는가"만 본다.

## 7. 커밋·브랜치

- 브랜치 `feat/<p0-id>-<짧은설명>`, `fix/…`, `exp/<ml-실험>`.
- 커밋 메시지 첫 줄은 한국어 요약, 본문에 설계서 절 번호(`설계서 5④-2`)와 P0 ID.
- PR은 체크리스트: 규약 2절(인덱스·튜플) 위반 없음, domain 변경에 테스트 동반, 비밀값 없음, 사용자 발화 로그 없음.

## 8. ADR

구조를 바꾸는 결정(스토어 도입, 벤더 교체, 감정 체계 변경)은 `docs/adr/ADR-NNNN-제목.md`에 배경·선택·대안·결과를 10줄 안으로 쓴다. 11/9 회의에서 정해질 항목(감정 체계 4/5감정, 기억 3층, 위험도 max 규칙)은 ADR 초안으로 미리 만들고 상태를 `제안`으로 둔다.
